## 压力闭环算法专家评审（仅评审，未改代码）

通读 pressure_controller.c / rbf_pid.c / pressure_ripple_comp.c / ramp_controller.c / motion_control.c 压力分支 / sim_pressure_control.c / 设计文档后给出评审。核心结论：四层架构（ffBase 前馈 + PI 反馈 + RBF 监督 + 纹波 FF）方向正确、嵌入式工程化达标，但有 5 个 P0 风险点：

1. **PI_RBF 监督模式世界模型不一致**：RBF_PID_Update 输出被丢弃，内部 u_prev/du_prev 按虚构轨迹演化，而 Jacobian 用(虚构 du, 真实 y)学习 → 输入输出对不自洽；每拍应回写实际 outputFlow 到 rbfPid.Output/u_prev/n_out（对照 RBF 主路径 597-599 行做法）。
2. **纹波环无幅值限制+高频失稳**：a1/rippleFF 无 clamp；τ=0.1s 对象在齿频相位 -72°(22rpm)~-86°(100rpm)，加 2ms 延迟即超 -90° → 无模型自适应对消可发散。需限幅+发散检测+按 K/τ 做动态增益相位补偿。
3. **systemGain=0 时 rippleEn 未检查、ffGain 残留 1/4.5 初值（比运行语义 1/90 大 20×）** → 过补偿。使能加 systemGain 检查，默认增益置 0。
4. **useEncoder=1 硬编码**：motorAngleRev 未接线时 theta 冻结，补偿静默失效。需相位推进检测+rpm 回退。
5. **motorAngleRev float 精度**：数万圈后分辨率恶化（~20 万圈后齿频相位误差 ~60°）。源头 wrap [0,1)。

P1：闸门只判|eP|不判|dP/dt|且两闸门阈值不一致(5/10bar)；ffTrim 每段清零 vs 纹波跨段保留（保压循环每模重学~1s 影响重量重复精度）；ffTrim+PI 双积分器需观察秒级 hunting；纯 RBF 策略丢弃 ffBase+rippleFF（纹波补偿仅 PI/PI_RBF 有效）；仿真 motor_tau=0/无延迟/扰动与补偿注入点不对称；"ff_cancel=99.2%" 是学习拟合优度而非物理对消率（真实看闭环 RMS~12%）。
P2：自监控诊断（corr/var 比上 HMI、符号错误自动禁用）、systemGain 在线辨识、EMA α 随转速自适应、2 次谐波启用、故障冻结策略。
