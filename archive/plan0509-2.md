## 二、`motion_planner.c` 详细评审（200 行）

### 2.1 ✅ 设计亮点

```c
if (input->segment->planner == HYD_PLANNER_POSITION_BASED) {
    return brakeVelocityMagnitude;   // 纯位置制动
}
rampVelocityMagnitude = ...;

```
时间规划模式下用 `min(斜坡速度, 制动速度)` 双重限制，既保证加速斜坡平滑，又确保提前制动不过冲，逻辑正确。

### 2.2 ❌ 问题一：仅支持梯形速度曲线，无减速段规划

**当前实现**：加速段用 `a·t` 线性爬升，无任何减速段规划。制动靠位置反馈实时计算 `√(2·a·d)` 逆推速度限制，是被动制动而非主动规划。

```c
// motion_planner.c#L56
velocityMagnitude = sqrt(2.0 * acceleration * remainingDistance);
// 这是制动距离公式，不是速度规划，无法预知减速起始点
```

**对注塑工艺的影响**：

| 工艺段 | 实际需求 | 当前问题 |
|--------|----------|----------|
| 快速合模→慢速护模 | 提前减速，平滑过渡 | 速度突降，液压冲击 |
| 高速注射末段 | 减速切换保压，V-P 平滑 | 速度/压力跳变 |
| 顶针缩回 | 到位前减速防撞 | 依赖外部位置触发，控制粗糙 |
| 座台进退 | S 曲线平滑 | 梯形曲线冲击前模 |

**根因**：缺少梯形速度规划的"减速起始点"计算：
```
S_brake = v_max² / (2·a)   ← 当 remainingDistance <= S_brake 时开始减速
```
目前 `√(2·a·d)` 正好等价于这个公式，但这只是"如果现在开始减速，最大允许速度是多少"，**不是完整的梯形规划**——加速段没有限制在合理的加速距离内，无法保证在目标速度下有足够的匀速段。

**优化方案：实现完整三段梯形规划**

```c
typedef struct {
    HYD_REAL t_acc;    // 加速时间
    HYD_REAL t_const;  // 匀速时间
    HYD_REAL t_dec;    // 减速时间
    HYD_REAL s_acc;    // 加速距离
    HYD_REAL s_const;  // 匀速距离
    HYD_REAL s_dec;    // 制动距离
} HYD_TrapezoidProfile;

static HYD_BOOL HYD_PlanTrapezoid(HYD_TrapezoidProfile* profile,
                                   HYD_REAL distance,
                                   HYD_REAL v_max,
                                   HYD_REAL acc) {
    HYD_REAL s_brake = (v_max * v_max) / (2.0f * acc);

    if (2.0f * s_brake >= distance) {
        // 距离不足以达到 v_max：三角形速度轮廓
        HYD_REAL v_peak = sqrtf(acc * distance);
        profile->t_acc   = v_peak / acc;
        profile->t_const = 0.0f;
        profile->t_dec   = profile->t_acc;
        profile->s_acc   = distance * 0.5f;
        profile->s_const = 0.0f;
        profile->s_dec   = distance * 0.5f;
    } else {
        // 标准梯形轮廓
        profile->t_acc   = v_max / acc;
        profile->s_acc   = s_brake;
        profile->s_dec   = s_brake;
        profile->s_const = distance - 2.0f * s_brake;
        profile->t_const = profile->s_const / v_max;
        profile->t_dec   = profile->t_acc;
    }
    return true;
}

// Execute 中根据 elapsed 和 profile 查当前速度
static HYD_REAL HYD_EvalTrapezoid(const HYD_TrapezoidProfile* p,
                                   HYD_REAL elapsed, HYD_REAL acc, HYD_REAL v_max) {
    if (elapsed < p->t_acc) {
        return acc * elapsed;                           // 加速段
    } else if (elapsed < p->t_acc + p->t_const) {
        return v_max;                                   // 匀速段
    } else {
        HYD_REAL t_dec = elapsed - p->t_acc - p->t_const;
        return HYD_ClampReal(v_max - acc * t_dec, 0.0f, v_max); // 减速段
    }
}
```

### 2.3 ❌ 问题二：`HYD_DIRECTION_AUTO` 输出速度为零

```c
// motion_planner.c#L9-L17
static HYD_REAL HYD_GetDirectionSign(HYD_MotionDirection direction) {
    switch (direction) {
        case HYD_DIRECTION_EXTEND:  return  1.0;
        case HYD_DIRECTION_RETRACT: return -1.0;
        default:                    return  0.0; // AUTO → 速度为零！
    }
}
```

`HYD_DIRECTION_AUTO` 经过 `HYD_Segment_ResolveDirection`（在 `segment_limits.c` 中）解析后理论上应已变为 EXTEND 或 RETRACT，但 `GetDirectionSign` 的 default 分支返回 0 是错误的兜底——任何解析失败或未解析的情况都会静默输出零速度，无诊断。

```c
static HYD_REAL HYD_GetDirectionSign(HYD_MotionDirection direction) {
    switch (direction) {
        case HYD_DIRECTION_EXTEND:  return  1.0f;
        case HYD_DIRECTION_RETRACT: return -1.0f;
        case HYD_DIRECTION_AUTO:    // 走到这里说明解析未完成，应上报
        case HYD_DIRECTION_HOLD:    return  0.0f;
        default:
```

### 2.4 ⚠️ 问题三：`velocityToFlowGain` 无单位文档，硬编码 fallback 为 1.0

```c
// motion_planner.c#L82-L85
gain = segment->velocityToFlowGain;
if (gain <= 0.0) {
    gain = 1.0;  // 硬编码 fallback
}
```

`gain` 是 `velocity(mm/s) → flow(L/min)` 的转换系数，其物理含义是液压缸面积。对不同缸径（φ50~φ200mm）此值差异可达 16 倍，fallback 为 1.0 在实际机台上会导致流量命令错误 10~50 倍。

**优化方案**：
1. `HYD_MotionSegment` 增加 `cylinderBoreArea`（缸径面积，mm²）字段
2. 由 `CreateMotion` 或全局配置注入，不在规划器内 fallback
3. 增加编译时断言：`gain <= 0` 时直接返回故障，而非静默使用错误值

### 2.5 ⚠️ 问题四：`HYD_MODE_SPEED_RAMP` 无减速段

速度斜坡模式（`HYD_ComputeSpeedRampVelocityMagnitude`）的加速段是正确的时间积分：
```c
velocityMagnitude = acceleration * elapsedTime; // 线性加速
```
但**没有对称的减速段**。只有当 `endCondition == HYD_END_POSITION` 时才有位置制动保护，其他结束条件（TIME / MANUAL）完全没有减速，运动停止时速度从 `v_max` 直接跳变到 0，产生严重液压冲击。

**注塑场景影响**：慢速合模（SPEED_RAMP + MANUAL）停止时液压冲击直接作用于模具合模面。

**优化方案**：增加时间基减速段——在 STOP 命令到来时启动减速计时器：
```c
// 在 HYD_MotionControlFB 增加
HYD_REAL _decelerationStartTime;   // 开始减速的时间点
HYD_REAL _decelerationStartVel;    // 开始减速时的当前速度
HYD_BOOL _isDecelerating;

// 规划器收到 STOP 命令后
if (fb->_isDecelerating) {
    HYD_REAL t_dec = elapsed - fb->_decelerationStartTime;
    vel = fb->_decelerationStartVel - segment->maxAcceleration * t_dec;
    if (vel <= 0.0f) {
        // 减速完毕，触发 DONE
    }
}
```

### 3.2 ❌ 问题一：滤波器默认 alpha=1.0，等同于无滤波

```c
// pressure_controller.c#L6-L7
#define HYD_DEFAULT_PRESSURE_FILTER_ALPHA             1.0  // 一阶低通 α=1 → 无滤波
#define HYD_DEFAULT_PRESSURE_DERIVATIVE_FILTER_ALPHA  1.0  // 微分滤波 α=1 → 无滤波
```

一阶低通滤波器公式：`y = α·x + (1-α)·y_prev`，当 `α=1.0` 时完全等于 `y=x`，滤波器形同虚设。

**对注塑工艺的影响**：
- 液压系统传感器采样普遍含有高频噪声（电磁干扰、油液脉动）
- 未滤波的压力信号直接进入 PID 微分项，会放大高频噪声，导致控制输出剧烈抖动
- 保压阶段（精度要求最高）反而是噪声影响最敏感的阶段

**优化方案**：

```c
// 根据典型注塑机液压系统特性设定合理默认值
// 压力传感器典型带宽 50Hz，PLC 周期 1ms → 截止频率建议 10~20Hz
// α = 2πfc·T / (1 + 2πfc·T) ≈ 0.06 for fc=10Hz, T=1ms
#define HYD_DEFAULT_PRESSURE_FILTER_ALPHA            0.1f  // 10Hz 截止，1ms 周期
#define HYD_DEFAULT_PRESSURE_DERIVATIVE_FILTER_ALPHA 0.05f // 微分滤波更强，5Hz 截止

// 同时在 Execute 中确保滤波器状态正确初始化
// 首次调用时：filteredPressure = measuredPressure（避免启动跳变）
if (state->firstCall) {
    state->filteredPressure = input->measuredPressure;
    state->filteredPressureRate = 0.0f;
    state->firstCall = false;
}
```

### 3.3 ❌ 问题二：PI 模式切换到压力控制时无 Bumpless Transfer

当从位置/速度控制段切换到压力闭环段时，`PrimeSegmentControllers` 调用：
```c
// motion_control.c#L349（推断自上下文）
initialPressureControlOutput = segment->targetFlow;
// 积分项初始化为 targetFlow（前馈）
```

**问题**：积分项初始化为 `targetFlow`（配方设定值），但切换瞬间的实际系统状态是：
- 实际压力 = 当前机械压力（可能远低于目标保压压力）
- 所需输出流量 = 实际流量（维持当前运动）

这导致切换后第一个周期 PI 输出 = `feedforward + kp·(目标-当前)大误差 + 已初始化积分`，产生输出跳变。

**注塑场景**：注射结束（高速、高流量）切换保压（低速/零速、压力控制），此时流量从 80L/min 骤降，控制器输出震荡。

**优化方案：基于实测状态初始化积分项**

```c
// HYD_PrimeSegmentControllers 中：
static void HYD_PrimeSegmentControllers(HYD_MotionControlFB* fb, ...) {
    HYD_REAL actualFlow    = HYD_MotionUtils_AbsReal(fb->AXIS_REF.flow);
    HYD_REAL actualPressure = fb->AXIS_REF.pressure;
    HYD_REAL targetPressure = segment->targetPressure;

    // Bumpless transfer：从当前实测流量初始化积分
    // 反推：output = feedforward + Kp·e + integral
    // → integral = actualFlow - feedforward - Kp·(targetP - actualP)
    HYD_REAL kp = (segment->pressureKp > 0.0f) ? segment->pressureKp : 0.5f;
    HYD_REAL e0 = targetPressure - actualPressure;
    HYD_REAL integral0 = actualFlow - segment->targetFlow - kp * e0;

    // 限幅并存入控制器状态
    HYD_REAL limit = (segment->pressureIntegralLimit > 0.0f)
                      ? segment->pressureIntegralLimit : segment->maxFlow;
    state->integralTerm = HYD_ClampReal(integral0, -limit, limit);
}
```

### 3.4 ❌ 问题三：PI 积分抗饱和仅限幅，无条件积分

```c
// pressure_controller.c#L154-L156（推断）
trackedIntegral = HYD_ClampReal(trackedIntegral, -integralLimit, integralLimit);
```

虽然有 back-calculation，但在**输出饱和**（流量达到 `maxFlow`）时没有停止积分的逻辑，积分项仍会在每个周期更新，导致：
1. 输出长时间饱和后积分项蓄积
2. 撤销饱和后控制器输出反向跳变（积分饱和效应）

**注塑保压场景**：保压建压阶段压力低于目标，误差持续为正，积分持续增长，输出打到 `maxFlow` 上限。一旦压力到达目标，积分项已大幅超调，导致压力过冲然后震荡。

**优化方案：条件积分（Conditional Integration）**

```c
// 在 PI/PID 执行中增加积分停止条件
HYD_BOOL shouldIntegrate = true;

// 条件1：输出未饱和
if (outputFlow >= resolvedConfig.outputMax ||
    outputFlow <= resolvedConfig.outputMin) {
    // 输出已饱和，且误差方向会继续推向饱和
    if ((error > 0.0f && outputFlow >= resolvedConfig.outputMax) ||
        (error < 0.0f && outputFlow <= resolvedConfig.outputMin)) {
        shouldIntegrate = false;
    }
}

// 条件2：误差在死区内
if (fabs(error) < resolvedConfig.deadband) {
    shouldIntegrate = false;
}

if (shouldIntegrate) {
    state->integralTerm += ki * error * dt;
    state->integralTerm = HYD_ClampReal(state->integralTerm,
                                         -integralLimit, integralLimit);
}
```

### 3.5 ⚠️ 问题四：PID 微分项使用误差差分，高噪声场景发散

```c
// 推断自 state->filteredPressureRate 的使用方式：
derivativeTerm = kd * (error - prevError) / dt;
```

误差差分微分在液压系统高频噪声环境下会放大高频扰动，即使加了导数滤波器（`derivativeFilterAlpha`），但默认 alpha=1.0（无滤波）时等于直接放大噪声。

**优化方案：改用测量值微分（Derivative on Measurement）**

```c
// 微分项作用在测量值上，而非误差上
// 避免设定值阶跃时产生微分冲击（Derivative Kick）
HYD_REAL filteredPrev = state->filteredPressure;  // 上一周期滤波后压力
// 本周期滤波
state->filteredPressure = alpha * input->measuredPressure
                        + (1.0f - alpha) * state->filteredPressure;
// 微分 = -Kd * d(measurement)/dt（负号：测量值增大时减小输出）
HYD_REAL derivativeTerm = -kd * (state->filteredPressure - filteredPrev) / dt;
```

### 3.6 ⚠️ 问题五：各工艺段使用相同 PI 参数，无增益调度

注塑机不同工艺段的液压系统特性差异极大：

| 工艺段 | 系统特性 | 最优控制参数 |
|--------|----------|------------|
| 高压锁模 | 高刚度，小误差 | 大 Kp，小 Ki |
| 注射保压切换 | 大惯性，快动态 | 中 Kp，抗饱和优先 |
| 稳态保压 | 低频扰动为主 | 小 Kp，大 Ki |
| 顶针保压 | 小缸径，高响应 | 小 Kp，快积分 |

当前实现所有段共用同一套 Kp/Ki/Kd，无法同时满足各阶段性能需求。

**优化方案**：增益调度（Gain Scheduling）

```c
// HYD_MotionSegment 增加工艺类型相关增益
typedef struct {
    HYD_REAL kpHigh;    // 大误差区（>20% 目标压力）的增益
    HYD_REAL kpLow;     // 小误差区（<5% 目标压力）的增益
    HYD_REAL errorBand; // 增益切换阈值
} HYD_GainSchedule;

// Execute 中根据当前误差幅度切换增益
HYD_REAL errorRatio = fabs(error) / targetPressure;
HYD_REAL kp_eff = (errorRatio > 0.2f) ? gs->kpHigh : gs->kpLow;
// 平滑插值避免切换时跳变
kp_eff = HYD_LerpReal(gs->kpLow, gs->kpHigh,
                       HYD_ClampReal(errorRatio / 0.2f, 0.0f, 1.0f));
```

### 4.2 ❌ 问题一：隐层重复计算，每次更新做两次前向传播

```c
// rbf_pid.c#L144-L158  rbf_update_network
static void rbf_update_network(RBF_PID_Handle *pid, float x_norm[RBF_INPUT_DIM],
                               float error_rbf, float y_hat) {
    (void)y_hat;  // ← y_hat 传入却被忽略！
    float h[RBF_HNUM];

    /* 前向计算隐含层输出（需要重新计算h，因为外部可能未保存）*/
    for (i = 0; i < RBF_HNUM; i++) {
        float norm_sq = 0.0f;
        // ... 重新计算 exp(-‖x-c‖²/2b²) 
    }
```

**问题**：`rbf_update_network` 在参数更新时**重新计算**了一遍隐层输出 `h[]`，而调用者（`RBF_PID_Execute`）在前向传播时已经计算过一次 `h[]`，且通过 `y_hat` 传入。但函数内 `(void)y_hat` 直接丢弃，导致每次更新都有一次多余的 `RBF_HNUM × RBF_INPUT_DIM` 次 `expf()` 计算。

`expf()` 是嵌入式平台上最昂贵的浮点运算之一，在 Cortex-M4 无 FPU 时每次约 100+ 时钟周期。6 个节点 × 3 个输入 = 18 次 `expf()`，重复计算每周期浪费约 1800 时钟周期。

**优化方案**：将 `h[]` 从调用方传入：

```c
// 修改函数签名
static void rbf_update_network(RBF_PID_Handle *pid,
                               float x_norm[RBF_INPUT_DIM],
                               const float h[RBF_HNUM],  // ← 传入已计算的 h
                               float error_rbf) {
    // 直接使用传入的 h，不再重新计算
    for (i = 0; i < RBF_HNUM; i++) {
        float delta_w = pid->eta_w * error_rbf * h[i];
        ...
    }
}
```

### 4.3 ❌ 问题二：固定随机种子初始化，多轴场景参数完全相同

```c
// rbf_pid.c#L31
static void rbf_init_network(RBF_PID_Handle *pid) {
    uint32_t seed = 12345UL;   // 固定种子，可重复
```

**问题**：固定种子 `12345` 导致所有轴的 RBF 网络初始化为**完全相同**的中心和权重。多轴系统中（合模缸 + 注射缸 + 顶出缸），三个 RBF-PID 实例的网络参数完全一致，无法分别适应各缸的不同液压特性，自适应学习过程也会走相同的路径，失去独立性。

**优化方案**：用轴索引扰动种子：

```c
void RBF_PID_Init(RBF_PID_Handle *pid, float sampling_period,
                  float max_motor_speed, float max_flow_rate,
                  uint8_t axis_id) {              // ← 增加轴ID参数
    ...
    // 用轴ID扰动初始种子，确保各轴网络差异化初始化
    uint32_t seed = 12345UL + (uint32_t)axis_id * 6364136223846793005ULL;
    rbf_init_network_with_seed(pid, seed);
}
```

### 4.4 ❌ 问题三：学习率固定为常数，保压稳态下过度学习导致漂移

```c
// rbf_pid.c#L89-L95
pid->eta_w = 0.25f;   // 所有学习率相同
pid->eta_c = 0.25f;
pid->eta_b = 0.25f;
pid->eta_p = 0.25f;
pid->eta_i = 0.25f;
pid->eta_d = 0.25f;
```

**问题**：注塑保压阶段系统已接近稳态，误差 < 0.5MPa，但 RBF 网络仍以 0.25 的高学习率持续更新参数，会在稳态下产生不必要的参数漂移和控制抖动。

保压稳定后理想状态是：PID 参数已收敛 → 降低学习率 → 保持当前参数。这是基本的自适应控制理论（e²-based learning rate decay）。

**优化方案：误差驱动的自适应学习率**

```c
// 根据误差大小自适应调整学习率
float error_norm = fabs(pid->Error) / (pid->Setpoint + 1e-6f);

// 误差大时高学习率（快速跟踪），误差小时低学习率（稳定保持）
float eta_scale = HYD_ClampReal(error_norm * 4.0f, 0.01f, 1.0f);
float eta_w_eff = pid->eta_w * eta_scale;
float eta_c_eff = pid->eta_c * eta_scale;
float eta_b_eff = pid->eta_b * eta_scale;

// 更新权重时使用自适应学习率
float delta_w = eta_w_eff * error_rbf * h[i];
```

### 4.5 ❌ 问题四：`RBF_HNUM`（隐层节点数）编译期固定，无运行时配置

```c
// rbf_pid.h（推断）
#define RBF_HNUM      6
#define RBF_INPUT_DIM 3
```

**问题**：
1. 6 个 RBF 节点是否足够覆盖注塑机液压系统的非线性？对高非线性的注射段（速度从 0 到 200mm/s 快速变化）可能不足，对稳定保压段则过多
2. `RBF_INPUT_DIM=3` 对应 `[du_prev, e, e_prev]`，缺少压力变化率（`dp/dt`）作为第四个输入，而压力动态恰恰是最重要的系统状态

**优化方案**：短期内无需动态化（嵌入式内存限制），但增加第四输入维度：

```c
// 增加压力变化率为第四输入
// x_norm[3] = (dp/dt) / (max_dp_dt)  ← 归一化压力变化率
float dp_dt = (pid->Feedback - pid->fLastActPress) / pid->sampling_period;
float dp_dt_norm = HYD_ClampReal(dp_dt / max_pressure_rate, -1.0f, 1.0f);
x_norm[3] = dp_dt_norm;
```

同时将 `RBF_INPUT_DIM` 改为可配置宏或运行时参数。

---

### 4.6 ⚠️ 问题五：PID 参数更新梯度推导使用数值近似，精度依赖假设

```c
// rbf_pid.c（Execute 中推断的 PID 参数更新）
// dJ/dKp ≈ error * du_prev（数值近似）
// 这实际上假设了系统的Jacobian ≈ sign(u→y)
```

RBF-PID 的自适应律需要系统 Jacobian `∂y/∂u`（输出对控制输入的偏导数），当前实现使用 `y_hat` 的近似来替代真实 Jacobian。对于液压系统，`u→y` 的关系是非线性的（流量-压力特性随负载变化），数值近似精度有限，在快速动态（注射段）时可能导致参数更新方向错误。

**优化方案（可选，研究性方向）**：
1. 将 Jacobian 符号（`sign(∂y/∂u)`）作为可配置参数，由工程师根据系统特性设定（液压系统通常为正定）
2. 增加 Jacobian 在线估计：`∂y/∂u ≈ Δy/Δu`（需保存上上周期的输出和输入）

```
开合模        射胶          保压          顶针         座台
  │            │             │             │            │
MoveAbs     MoveVel       PressHandle   MoveAbs      MoveAbs
  │          + MoveAbs        │            │            │
  ↓            ↓             ↓             ↓            ↓
PositionPlanner SpeedRamp  PressureCtrl  Position    Position

              ↕V-P切换❌
```

**跨模块问题**：规划器输出的 `targetFlow` 直接作为压力控制器的 `feedforwardFlow`，但：
- 规划器输出无单位对齐验证（mm/s × gain = L/min，gain 来源不同模块）
- 切换时规划器归零但压力控制器积分未重置（Bumpless Transfer 问题的跨模块体现）
- RBF-PID 的学习状态跨段持久化存储在 `HYD_MotionControlFB` 中，但 SoftReset 会清除它，导致每次复位后 RBF 从头重新学习
