## 1. 归档原则

### 1.1 归档条件

满足以下任一条件的文档应考虑归档：

1. **内容已被新文档取代**：相同内容在新文档中有更完整、更准确的描述
2. **阶段性成果已过时**：某个阶段的工作成果，已被后续工作覆盖或替代
3. **参考价值有限**：仅作为历史记录，不再作为当前工作指导
4. **存在冲突矛盾**：与其他文档存在矛盾，以最新文档为准

### 1.2 保留原则

以下类型的文档不归档，继续保留在项目根目录：

1. **当前活跃文档**：正在使用和频繁更新的核心文档
2. **权威参考文档**：被广泛引用的标准文档
3. **模板文档**：需要频繁使用的模板文件
4. **配置文件**：项目构建和配置相关文件

## 5. 维护建议

### 5.1 新文档处理

当需要创建新文档时：
1. 评估文档性质：核心文档/支撑文档/历史文档
2. 选择存放位置：根目录/支撑目录/archive目录
3. 参考现有模板：确保格式和风格统一
4. 更新交叉引用：确保相关文档引用正确

### 5.2 旧文档处理

当发现需要归档的文档时：
1. 确认归档条件是否满足
2. 创建归档说明文档
3. 移动文档到archive目录
4. 更新相关文档的引用
5. 通知团队成员归档变更

### 5.3 归档目录维护

定期检查和维护归档目录：
1. **每季度检查**：是否有新文档需要归档
2. **每年整理**：归档文档是否还有参考价值
3. **过期处理**：超过3年且无参考价值的文档可删除

## 6. 注意事项

### 6.1 归档注意事项

1. **不删除有价值内容**：即使文档过时，如果有参考价值，仍应保留
2. **保持完整性**：归档文档保持原样，不做修改
3. **建立索引**：归档文档需要有清晰的索引和说明
4. **版本控制**：归档操作通过Git提交，保留历史

### 6.2 查阅注意事项

1. **优先查阅最新文档**：归档文档仅供参考，以最新文档为准
2. **注意时效性**：归档文档可能已过时，需要注意时效性
3. **交叉验证**：重要问题需要查阅多份文档交叉验证
4. **寻求确认**：不确定时向项目负责人或文档负责人确认

### 6.3 维护注意事项

1. **及时更新**：核心文档需要及时更新，保持准确性
2. **版本控制**：所有文档变更通过Git管理，保留历史
3. **团队沟通**：重大文档变更需要团队沟通确认
4. **质量保证**：文档发布前需要质量检查，确保准确性
