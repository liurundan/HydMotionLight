# RBF-PID 压力闭环控制算法 —— 工程实用性评估与优化方案

> 评估日期：2026-09-17
> 评估对象：`src/rbf_pid.c` / `include/rbf_pid.h`（RBF 神经网络自适应 PID）+ `src/pressure_controller.c` 接线
> 评估方法：**代码走查 + 实测探针**（不依赖理论断言）
> 植物：`src/sim/PressureModel.c`（物理标定模型），生产链路配置 25cc/rev @1700rpm、η=0.95、管路 3.5m
> 判据：稳定性 / 快速性(tr, ts) / 超调 Mp≤5% / 稳态误差 |ess|≤1 bar / 稳态纹波 σ≤1 bar

---

## 0. 一句话结论

**当前 RBF-PID 不具备工程实用性 —— 但它"看起来能用"，这才是最大的风险。**

实测证明：RBF 神经网络对控制输出**贡献为零**（Jacobian 100% 时间被钉死在限幅边界），
算法实际退化为"**一组未经整定、本应失稳的固定增益 + 一个把输出钳死到 0.5 L/min 的流量上限**"。
它之所以满足指标，是因为**输出被钳位掩盖了增益的不稳定**，而非因为整定得当或自适应的功劳。

在同样的前馈/包络条件下，**正确整定的固定增益 PI 在 7 项指标中的 5 项优于 RBF，
其中上升时间快 3.7 倍、扰动恢复快 117 ms**，而 RBF 唯一占优的 Mp（0.22% vs 1.04%）
两者都远低于 5% 门槛，**该优势没有工程价值**。

## 1. 算法结构梳理（先看清它到底是什么）

当前实现并非"RBF 整定 PID"，而是**六层机制的叠加**：

| 层 | 机制 | 代码位置 | 作用 |
|---|---|---|---|
| L1 | 速度式（增量）PID | `rbf_pid_step_incremental_output` | `du = KP·Δe + KI·e + KD·Δ²e`；`u = u_prev + du` |
| L2 | RBF 网络辨识 Jacobian | `rbf_pid_step_rbf_nn` | 6 隐节点，输入 `[Δu/5, P(k-1)/250, P(k-2)/250]`，输出 `∂P/∂Δu` |
| L3 | 梯度法自适应 KP/KI/KD | `rbf_pid_step_adaptive_gains` | `ΔKp = ηp·e·sign(J)·|J|·Δe` 等 |
| L4 | 稳态前馈播种 | `RBF_PID_Update` 开头 | 设定值跳变 >5 bar 时把 `u_prev` 播种到"超调驱动上限" |
| L5 | 多重流量上限 | `rbf_pid_effective_soft_cap` | 软上限 `1.05·P_set/K` ⊕ 超调上限 ⊕ 升压包络 ⊕ 外部流量钳位 |
| L6 | 相位分离积分限幅 | `rbf_pid_step_incremental_output` | 升压/逼近/窄带三档不同的积分钳位 |

**关键认知：真正决定性能的是 L4/L5（开环成型），不是 L2/L3（神经网络自适应）。**
下面用实测证明这一点。

### 1.1 实测植物参数（开环辨识，可复现）

```
阶跃 20 rpm（Q = 0.475 L/min）→ P_ss = 100.67 bar
K_q  = P_ss / Q      = 210.55 bar/(L/min)      （名义设计值 200，偏差 +5%）
t63  = 1.862 s       → τ = 1.862 s
一步灵敏度 b = K_q·(1 - e^(-dt/τ)) = 0.11305 bar/(L/min)
```

> ⚠️ 这个 `b` 是理解全部缺陷的钥匙，见 §2.1。

## 2. 缺陷清单（按严重度排序，全部有实测证据）

### D1【致命】RBF 自适应完全失效 —— 神经网络对输出零贡献

**机理（量纲错误）**

`rbf_pid.c:364-373` 用**稳态增益 K** 给 Jacobian 限幅：

```c
if (pid->K > 0.0f) {
    float jac_lo = pid->K * 0.2f;      // K=200 → 40
    float jac_hi = pid->K * 5.0f;      //        → 1000
    ...
}
```

但网络辨识的量是 **一步灵敏度** `∂P(k)/∂Δu(k-1)`。对一阶对象：

```
P(k) = a·P(k-1) + b·u(k-1),   a = e^(-dt/τ),  b = K_q·(1-a)
u(k-1) = u(k-2) + Δu(k-1)
⇒ ∂P(k)/∂Δu(k-1) = b = K_q·(1 - e^(-dt/τ)) ≈ K_q·dt/τ
```

**`b` 与 `K` 相差 `τ/dt` 倍 ≈ 354 倍。** 用 K 去限幅 b，等于把窗开在了完全错误的位置。

**实测（`out/tmp/probe_rbf.c`，阶跃 0→150 bar，3000 采样）**

```
真实一步灵敏度 b = 0.113 bar/(L/min)
代码限幅下界 0.2K = 40.0   →  膨胀 354 倍

Jacobian: min -40.000  max 40.000  mean 36.05
          触下界(0.2K) 3000 次, 触上界(5K) 0 次     ← 100% 在边界，从未进入区间内部

KP 撞下限 47.7%, 撞上限 49.0%   [窗 0.400..0.900]
KI 撞下限  4.9%, 撞上限 95.1%   [窗 0.0013..0.0056]
KD 撞下限  0.5%, 撞上限 96.3%   [窗 0.015..0.035]
自适应有效活动窗（KP/KI/KD 均不在限幅上）: 3.2%（带噪声时 0.6%）
```

**两个后果**

1. **梯度放大 354 倍** → 每拍增量远超窗口宽度 → 增益在上下限之间 bang-bang 抖动。
2. **符号随机翻转**：Jacobian 在 +40 / −40 之间逐拍跳变（t=1,2 为 −40；t=3,4,5 为 +40）。
   因为网络输出没有有效梯度信息，其符号本质是噪声，而 `sign(Jacobian)` 直接决定了梯度方向。

> **结论：RBF 网络输出的是一个"符号随机翻转的饱和常数"，不是辨识结果。**

### D3【致命】稳定性来自"输出被钳位"，而非整定 —— 隐式且脆弱

同一组增益（RBF 实测被钉住的 KP=0.9 / KI=0.0056），**唯一变量是有没有软上限**：

| 配置 | ess/bar | σ/bar | 输出波动幅度 | 判定 |
|---|---|---|---|---|
| 无软上限（裸增益） | 14.507 | 5.162 | 7.775 L/min | ★失稳 |
| 有软上限 `1.05·P/K` = 0.525 L/min | -2.255 | 0.477 | 0.356 L/min | σ达标，ess仍超标 |
| 临界阻尼整定（无上限） | **-0.006** | **0.698** | 0.919 L/min | **达标** |

**软上限把可用输出范围从 20 L/min 压缩到 0.525 L/min（38 倍）→ 有效环路增益被同比压低 →
掩盖了增益本身的不稳定。**

这正是"看起来能用"的根源：**算法稳定是因为它被限幅器压住了，不是因为它被整定好了。**
风险在于：稳定性隐式依赖"K 标定正确"和"上限存在"两个前提，任一失效即暴露（见 D4）。

### D4【严重】K 高估 → 永久性、无诊断的**稳态欠压**

**机理（解析）**

软上限 `Q_cap = P_set·1.05/K_used`，升压包络在 `e→0` 时收敛到 `Q_cap`，
**在稳态同样生效**。于是闭环平衡点被这个天花板约束：

```
P_eq  满足  P_eq = K_true · [ Q_cap + (Q_boost − Q_cap)·(P_set − P_eq)/(0.5·P_set) ]
```

当 **K_used 高估**（`K_used > K_true`）→ `Q_cap` 偏小 → `P_eq < P_set` → **永久性静差**。
更糟的是速度式反算（`u_prev = clamp(u)`）会把积分状态**钉在天花板上**，积分永远救不回来。

**实测 + 解析互证（保压 100 bar，K_used 固定 200）**

| 真实植物 | K_true | 解析预测 ess | 实测 ess |
|---|---|---|---|
| 泄漏×2（K_used 高估 1.9×） | 105.8 | **-1.743 bar** | **-1.943 bar** ✅吻合 |

> **方向性危险**：K 高估 → **欠压**。注塑机欠压 = 缺料 / 短射 / 缩痕，是**废品方向**，
> 且系统无任何诊断输出（不报警、不置位）。

### D5【严重】在线辨识在本工况**物理上就不可行**（缺乏持续激励）

这是比 D1 更根本的问题：**就算修好了 D1 的量纲错误，RBF 也学不到东西。**

实测两版在线辨识器：

| 方法 | 结果 |
|---|---|
| 2 参数 LMS（`P(k+1)=a·P(k)+b·Q(k)`） | **发散**：K_est → 10，ess → 30 bar，偏差 42~120 bar |
| DC 工作点法 `K = P/Q`（低通+稳态门控） | 稳定但**系统性偏 +27%**：测 266 vs 真 210；测 532 vs 真 420 |

**根因**
- 保压稳态是**恒设定值、恒输出**工况 → **没有持续激励（PE 条件不满足）** → 闭环辨识本就病态。
- DC 法的偏差来自**泵内漏**：`pump_flow` 是排量流量，未扣除泵内部泄漏，故 `P/Q_pump` 系统性偏大。

**推论：RBF 承诺的"在线适应对象变化"在本工况不成立。** 这也解释了为什么
`K` 漂移 ×2 时 RBF 的 ess 恶化到 -3.867 bar —— 它根本没在适应。

## 3. 与其他算法的横向对比（工程视角）

| 算法 | 优势 | 劣势 | 本场景适用性 |
|---|---|---|---|
| **PI / PID（整定后）** | 结构极简、可解析整定、确定性、零调参负担 | 需知道 K、τ；工况剧变时需重新整定 | ★★★★★ **推荐** |
| **前馈+PI（推荐方案）** | 前馈吃掉稳态流量（K），PI 只管残差 → 快速性与鲁棒性解耦 | 需 K | ★★★★★ **推荐** |
| **RBF-PID（当前）** | 理论上可适应非线性/时变 | 实测自适应失效；量纲错误；增益窗未整定；不可复现；CPU 有 6 次 `expf()` | ★☆ **不推荐** |
| 模糊 PID | 不依赖精确模型，规则可解释 | 规则库靠经验；稳态精度差；保压纹波难压到 1 bar | ★★ 可选 |
| ADRC（自抗扰） | ESO 观测总扰动（含 A·v 负载流）并补偿，对扰动极强 | 需调 β01/β02/β03 + b0；带宽受采样限制 | ★★★★ **值得评估**（扰动是注塑保压的主要矛盾） |
| MPC | 显式处理约束（溢流阀、转速限） | 需在线求解；1 ms 周期难落地；模型依赖强 | ★★ 周期允许时（≥5 ms）可考虑 |
| 滑模 | 强鲁棒 | 抖振 → 直接恶化稳态纹波 | ★ **不适用**（与 σ≤1 bar 冲突） |

**为什么 ADRC 值得单独提**：注塑保压段的主要扰动是**螺杆前移造成的负载流量 `A·v_load`**
（V-P 切换、保压补缩）。实测 0.15 L/min 的负载流阶跃会造成 2.7 bar 偏差。
ESO 能把 `A·v_load` + 泄漏变化一并观测为"总扰动"并前馈补偿，
**这比让神经网络去猜 Jacobian 更直接、更可解释、更有物理依据。**

## 4. 优化方案

### 4.1 立即修复（保守、低风险、不改架构）

| # | 修复 | 针对 | 预期收益 | 已验证 |
|---|---|---|---|---|
| **P1** | **软上限在窄带内解除**：`\|e\| < 5%·P_set` 时不再施加 `1.05·P_set/K` 上限，交回积分 | D4 | K 高估 1.9× 时 ess **-1.943 → -0.000 bar** | ✅ 实测 |
| **P2** | 增加诊断：**输出顶到软上限 + 误差持续 >N 拍** → 置位报警（防"静默欠压"） | D4 | 消除"压力打不到还不报警" | 待实现 |
| **P3** | 把增益窗口改为**按实测植物整定**：KP∈[0.15,0.35]、KI∈[0.001,0.003]、KD∈[0,0.01]；或改为**由 K、τ 在线计算**（极点配置） | D2 | 从"靠限幅压住"改为"真的稳定" | ✅ 网格扫描已定位稳定区 |
| **P4** | 清理废弃代码（f_velfb / accel_ff / network_seed / 两个降级字段） | D6 | 消除误导 | 待实现 |
| **P5** | 学习停滞判据 `STEADY_DEAD_ZONE` 10 bar → 0.5 bar（或按 `1%·P_set`） | D6 | 让自适应在有意义的范围生效 | 待实现 |

**P1 修复实测（`out/tmp/probe_fix.c`）**


> 且不需要为 K 误差预留裕度（不牺牲升压速度）。

### 4.2 中期重构（推荐路线：砍掉 RBF，换成可解析整定的前馈+PI）

**目标架构**

```
                    ┌────────────── 稳态前馈 Q_ff = P_set / K  ─────────────┐
                    │  （吃掉 95% 的稳态流量，K 由泵铭牌推导或现场标定）      │
   P_set ──(+)──► [ 速度式 PI ] ──(+)──► [ 升压制动包络 ] ──► Q ──► 泵
             ▲        只管残差        仅升压瞬态收紧(窄带解除)
             │
        P_measured
                    └──── 可选：ESO 观测 A·v_load 负载流并前馈补偿 ────┘
```

**增益由植物参数解析整定（不需要任何学习率）**

```
K_q = Ksys / (D/1000)              [bar/(L/min)]   泵铭牌 + 现场标定
τ   = V·K_q / βe                   [s]             或由开环阶跃 t63 直接测
ζ = 1（无超调），ωn 取稳定边界的 70%（实测边界 wn≈18 → 取 12~14 留裕度）
KP = (2·ζ·ωn·τ − 1) / K_q
KI = ωn²·τ / K_q · dt              （速度式）
```

**预期收益（实测对照，§2.7 表）**：tr 321→87 ms（**3.7×**）、ts 508→309 ms、
扰动 2.69→1.11 bar、恢复 117→0 ms；Mp 由 0.22% 升到 1.04%（仍远低于 5% 门槛）。

**额外收益**
- 消除 6 个学习率 + 3 组限幅窗 + 网络初值 = **12+ 个无物理意义的调参量**
- 消除每周期 6 次 `expf()`（Cortex-M 上约 3-6 μs）
- 行为**确定性可复现** —— 这对量产设备的工艺一致性是刚需

### 4.3 长期（若确实需要"自适应"）

按性价比排序：

1. **增益调度（Gain Scheduling）**：按 `P_set` 分段整定 —— 本植物的 `K` 随压力
   （含气量/油液刚性）变化，实测低压段有效增益偏低。**用查表代替神经网络**，可解释、可验证。
2. **ESO/ADRC 补偿负载流**：把 `A·v_load` 当"总扰动"观测补偿，直接命中注塑保压的主要矛盾。
3. **K 的离线/开机自标定**：在**升压瞬态**（有激励）做一次最小二乘辨识，而不是在稳态瞎学。
   注意避开 D5 的两个坑：PE 条件 + 泵内漏偏差。
4. **不要**继续投入 RBF：本工况下它连"可辨识"的前提都不满足。

## 5. 风险与遗留（诚实声明）

- **全部结论基于仿真植物**（`PressureModel.c` 物理标定模型）。虽然该模型按 3.5m/12mm
  真实几何标定过，但**不能替代上机首台验证**。
- `K_q = 210.55` 与名义设计值 200 差 +5%，说明**铭牌推导的 K 有约 5% 固有误差**，
  这在 D4 机制下会直接转化为静差 —— 进一步支持 P1 必须做。
- §4.2 的"稳定边界 wn≈18"是**本植物本噪声水平**下的实测值；不同机型（不同 V、βe、
  管路长度）**必须重新扫描**，不可照搬。
- D5 的 DC 辨识 +27% 偏差来自泵内漏；若要用，**必须用腔体净流量或做一次性标定**，
  不能直接取 `pump_flow`。
- 本次未实施任何源码修改，仅给出方案与实测依据；§4.1 的 P1 已用离线探针验证有效，
  但**尚未接入 `src/rbf_pid.c`**。

## A.3 落地过程中发现并修掉的三个坑（都很隐蔽）

### 坑 1：新增策略没进白名单 → 压力段根本不启动
`recipe_validator.c` 的 `HYD_IsValidPressureControllerType` /
`HYD_IsSupportedPressureControllerType` 是两份**逐字相同**的策略白名单。
FF_PI 没加进去 → 所有压力段被判 `SEGMENT_INVALID`（ERRORID=3）→ 段不启动
（`_activeSegment.maxFlow` 恒 0）→ 表现为"压力毫无响应"。
症状离根因极远，5 个测试同时变红才定位到。已在两处函数上方写死注释：
**加新策略必须同步改这两个函数**（另一处是 `motion_control.c` 的
`HYD_IsValidPressureControllerParameter` 上界）。

### 坑 2：legacy 名义保压流量与 Q_ff 叠加 → Mp 33%
`segment->targetFlow`（出厂 `defaultTargetFlow = 5.0 L/min`）是"没有对象模型时代"
的占位常量，物理上根本不成立：`5.0 × K(200) = 1000 bar`。
FF_PI 的 `Q_ff` 若与它叠加，实测（生产链路，目标 150 bar）：

- 叠加时：升压包络把压力卡在内漏平衡点 **137 bar** → 进入窄带解除区 → 上限突然放开
  → 5.0 的幽灵前馈把压力直接顶到 **200 bar（Mp 33.49%）**。
- 改为 **Q_ff 取代（而非叠加）** legacy 前馈后：**Mp 2.42%**（窄带 0.05 时）/ 3.20%（0.07 时）。

追踪证据：`tests/diagnostics/probe_prod_trace.c`（t=0 时未削顶输出 23.0 L/min）。

### 坑 3：窄带宽度是"可达性 vs 超调裕度"的硬权衡
窄带解除太晚，K 高估时比例项的静平衡点
`P_eq = (K·Q_ff + K·kp·P_set)/(1 + K·kp)` 落在解除区**之外**，
包络把压力永久卡在 `P_eq`、积分被抗饱和锁死 → 又变回 D4 那种静默欠压。
生产链路实测（Mp%，P=3/3 达标 / F=未达标；K 真值≈210.55）：

| 窄带 | K=100 | K=200 | K=300 | K=380 | K=500 |
|---|---|---|---|---|---|
| 0.05 | 7.79F | 2.42P | 0.86P | 0.44P | **-6.07F（卡死在 141.9 bar）** |
| 0.06 | 7.79F | 2.91P | 0.86P | 0.44P | **-6.07F（卡死）** |
| **0.07** | 8.45F | **3.20P** | 0.99P | 0.46P | **0.66P** ← 采用 |
| 0.08 | 9.36F | 3.67P | 1.10P | 0.73P | 0.79P |
| 0.10 | 10.37F | 4.52P | 1.65P | 1.05P | 0.95P |
| 0.15 | 14.29F | **6.75F** | 3.35P | 1.85P | 1.69P |

**0.07 是拐点**：能救回 K 高估 2.5× 的最小值，名义点仍留 1.8 pp 超调裕度。
该常数由 `tests/test_ff_pi_contract.c [5]` 回归保护。

## A.4 带宽与鲁棒性（生产链路实测，`scan_prod_bandwidth.c`）

| τ 配置 | ωn=8 | ωn=12（默认） | ωn=16 | ωn=20 | ωn=24 |
|---|---|---|---|---|---|
| **出厂默认（τ=1.0，低估）** | PASS | PASS | PASS | PASS | PASS |
| 现场标定 τ=1.862 | PASS | PASS | PASS | FAIL(σ1.65) | FAIL(σ4.10) |
| τ 高估 2.5 | PASS | PASS | FAIL(σ3.62) | FAIL | FAIL |

**结论**：τ 默认 1.0（刻意低估真值 1.862）确实在安全侧 —— ωn 一路开到 24 都 3/3。
**现场一旦标定 τ，ωn 必须相应收**（τ=1.862 时 ωn 上限约 16）。

另有一个反直觉但重要的实测事实：**tr 在 ωn=8~24 全区间恒为 265 ms**。
升压段的耗时由**制动包络**决定，不是由环路增益决定。
→ 想加快建压，要动 `boostBrakeFrac`，不是动 ωn。
