# RBF-PID 压力闭环算法评审报告

- 评审对象：`src/rbf_pid.c`、`src/pressure_controller.c`（含 `include/rbf_pid.h`、`include/pressure_controller.h`、`rbf_pid_formulas.md`）
- 集成上下文：`src/motion_control.c:2121-2141`（仅 `HYD_MODE_PRESSURE_CLOSED_LOOP` 段调用压力闭环）
- 评审日期：2026-08-31
- 评审定位：结合液压注塑机实际工况，评估算法正确性、完善程度与动作适用性

---

## 1. 架构概述

调用链：`HYD_PressureController_Execute()` →（RBF 策略）`HYD_ApplyRbfPidConfig()` → `HYD_SynchronizeRbfPidState()`（策略切换/跟踪时全量复位）→ `RBF_PID_Update()`。

策略表（pressure_controller.c:51-57）：P / PI / PID（经典）+ RBF_PID / RBF_PI（自适应）。

RBF-PID 由四部分组成：

1. **RBF 在线辨识器**（6 隐含层节点，输入 `[Δu(k-1), y(k-1), y(k-2)]` 归一化，预测 ŷ(k)）
2. **Jacobian 估计**（∂ŷ/∂x[0] ≈ ∂y/∂Δu，供 PID 参数整定）
3. **PID 参数在线整定**（梯度律 + 若干启发式：L2 积分惩罚、微分"强制唤醒"）
4. **增量式输出级**（Δu 累加 + 前馈 + 软流量限幅 + 饱和标记）

设定值经过 ramp 斜坡（motion_control.c:2122 传入 `rampedPressure`），避免了设定值阶跃冲击——这一点设计合理。

## 2. 完善程度评估

**已成体系的部分**

| 维度 | 评价 |
|---|---|
| 控制律主框架 | 增量式 PID + RBF 辨识 + 梯度整定，与 `rbf_pid_formulas.md` 第 2/4/5/7/8 章公式一致（权值/中心/宽度更新律逐条核对无误） |
| 无扰切换 | `RequestTracking` + `SynchronizeRbfPidState` 用外部跟踪流量预置 `u_prev`，且外钳位结果写回 `u_prev`（pressure_controller.c:582-584），形成事实上的抗饱和回算，设计良好 |
| 经典分支 | 微分作用于反馈量（:609，避免设定值冲击）、条件积分抗饱和（:637-641）、kpHigh 增益调度（:600-605）、积分按 dt 归一（:629）——实现规范，是整个文件里质量最高的部分 |
| 归一化 | 压力/流量双标尺，随泵配置（`pumpSpeedLimit / flowToPumpSpeedGain`）推导 `fMaxFlow`，链路清晰 |
| 测试 | `tests/rbf_pid_test.c`、`tests/test_pressure_controller.c` 有基本回归覆盖 |

**未实现的部分**

- 公式手册第 9 章 **Smith 预估器（时滞补偿）**、第 10 章 **在线增益辨识**：代码中完全没有对应实现，`K`（systemGain）只是静态配置且仅作用于软流量限幅。文档描述的架构与代码实现存在缺口。
- 段级配置 `pressureDeadband`、`pressureFilterAlpha`：被解析（:243-244）但从未参与计算，配置 API 形同虚设（见缺陷 #8、#9）。

总体完善度：**主框架中等偏上，理论宣称的补偿环节缺位，且默认模式（PID）的数值防护明显弱于 PI 模式**。

## 3. 算法错误与缺陷清单

### P0 — 正确性 / 安全性，建议优先修复

| # | 位置 | 问题 | 影响与建议 |
|---|---|---|---|
| 1 | rbf_pid.c:617-620, 291-298, 527-528 | **默认 PID 模式主链路无 NaN/Inf 防护**：输入清洗、网络清洗、du 非有限值归零全部只在 PI 模式执行 | 传感器毛刺一旦产生 NaN，将经 `expf`/权重累加传染到泵速指令。嵌入式压力闭环这是安全隐患。建议把 sanitize 逻辑改为两种模式共用，或在入口统一做有限值检查 |
| 2 | rbf_pid.c:351 | **PID 模式下权重 `w` 无界更新**：`pid->w[i] += delta_w` 不做钳位；`rbf_pid_sanitize_network` 仅 PI 模式调用（:292） | 权重可发散 → Jacobian 与输出失真。建议所有模式统一使用 `RBF_PID_WEIGHT_LIMIT` 钳位 |
| 3 | rbf_pid.c:133 vs rbf_pid.h:21 | **初始 KP=0.04 低于自身下限 min_KP=0.4**：自适应律更新后才钳位，独立调用时首拍会出现 0.04→≥0.4 的增益阶跃 | 控制器路径靠 pressure_controller.c:354 外部钳位掩盖了问题；独立实例（如测试/复用）会踩中。建议初始化即钳位到参数窗内 |
| 4 | rbf_pid.c:514-516, 200, 706-715 | **压力加速度前馈开关失效**：`f_uff` 被连续赋值两次（第二次硬编码 -0.15·Δ²P），`pressure_accel_ff_enabled` 从未参与输出决策 | `RBF_PID_SetPressureAccelFeedforwardEnabled()` 与 PI 模式的强制禁用都是名义功能。要么把开关接回输出路径，要么删除该 API，避免误导集成方 |
| 5 | rbf_pid.c:348-372 | **w/c/b 更新顺序错误**：`delta_center`、`delta_b` 使用了本拍已被更新的 `w[i]`（w 先原地更新） | 与同步梯度下降假设不符，引入系统性学习偏差。应先缓存旧 w，或用旧值统一计算三个增量后再落盘 |

### P1 — 性能 / 行为一致性

| # | 位置 | 问题 | 影响与建议 |
|---|---|---|---|
| 6 | rbf_pid.c:504 | **增量控制律未按采样周期归一**：`du = KP·Δe + KI·e + KD·Δ²e` 中 `sampling_period` 只用于稳态计数（:556），从不进入控制律 | 单位时间的积分/微分作用强度与环频率成反比；实际环周期抖动或被慢速任务调用时增益漂移，且与经典分支（:629 使用 `ki·e·dt`）口径不一致。建议 Δe、Δ²e 除以 dt（或约定固定环频并在文档中锁死） |
| 7 | rbf_pid.c:503, 523 | **du 与积分项钳位为硬编码绝对值**（±0.5、±0.08 L/min），不随泵容量/输出量程缩放 | 大流量机型响应被强压、建立压力慢；小流量机型可能过激。建议按 `fMaxFlow` 或 `output_max_flow` 的百分比缩放 |
| 8 | pressure_controller.c:508 | **压力反馈未做低通滤波**：`filteredPressure = input->measuredPressure` 直接透传，`filterAlpha` 解析后未使用 | 液压系统泵脉动/阀切换噪声直接进入 D 项（二阶差分放大噪声）→ 泵速指令抖动。微分通道已有 `derivativeFilterAlpha`，但压力本体滤波应补上 |
| 9 | pressure_controller.c:243 | **`pressureDeadband` 对所有策略均未生效** | 段配置字段无效，建议接入误差通道或删除字段 |
| 10 | rbf_pid.c:393-401 | **软流量限幅 `P_set·1.05/K` 用稳态增益约束瞬态流量** | 建压瞬态流量主要消耗在油液压缩（Q=V/β·dP/dt），与稳态泄漏量级不同；systemGain 较大时该限幅会"饿死"建压流量，拖慢升压。建议仅在稳态/保压阶段启用，或改为与建压速率需求挂钩 |
| 11 | rbf_pid.c:272, 553 | **学习冻结阈值 10 bar 且注释写 "MPa"**（项目压力制为 bar）；与稳态判据 `e_steady=5 bar`（:553）两套标准不一致 | \|e\|<10 bar 即冻结学习，意味着保压精调段几乎全程不学习，自适应收益被大幅削弱；注释单位错误易误导后续维护。建议统一阈值并修正注释 |
| 12 | pressure_controller.c:565 vs :648 | **负流量死区阈值不一致**：RBF 分支 `fabs(error)<5.0`，经典分支 `error>-2.0`；:564 注释写的是 2.0 | 同一超压工况在不同策略下行为不同（2 bar 超压时经典分支已泄流、RBF 分支不泄），注释与代码不符。建议统一阈值并修正注释 |
| 13 | pressure_controller.c:557-570 | **RBF 分支不叠加 `feedforwardFlow`**：经典分支输出 = 前馈 + 反馈（:644），RBF 分支只用 `rawOutputFlow - feedforwardFlow` 做账面量 | `segment->targetFlow` 前馈在 RBF 策略下丢失，两种策略切换时输出基线不同，可能引起切换扰动 |
| 14 | pressure_controller.c:404, 539 | **策略切换/跟踪请求即全量复位**（`RBF_PID_Reset` 重建网络初值） | 注塑一个周期内多段切换，学习成果从不跨段保留，"在线学习"实际退化为每段从零开始。建议至少保留已收敛的 w/c/b，只复位控制器状态 |

### P2 — 可维护性 / 设计瑕疵

|---|---|---|
| 15 | rbf_pid.c:625, 403, 533-535, 326；rbf_pid.h:77-80 | 死代码：`control_state` 状态机（INIT/BOOST/HOLD/RELIEF）计算后从未消费；`rbf_pid_target_relative_learning_scale()` 无调用者；`ff_flow` 计算后丢弃；`dde` 未使用；`gain_compensation_factor` 从不作用于输出——头文件宣称的"输出末端兼容补偿"与实现不符（`K` 实际只影响软限幅） |

## 4. RBF-PID 方案优劣小结

**优势**

1. 增量式结构天然无积分饱和、无扰切换友好，配合跟踪/回写设计，工程化程度较好。
2. 辨识器 + Jacobian + 梯度整定的框架在理论上自洽（Δu 口径对增量式 PID 成立，公式手册第 5/7 章的口径辩护是合理的）。
3. PI 模式下数值防护、饱和同向学习冻结（:246-269）等细节考虑周到。

**劣势 / 风险**

1. **辨识前提被削弱**：du 维度动态范围太小（见 #17），Jacobian 质量存疑，而 Jacobian 是整定律的方向依据——方向错则 KP/KI/KD 往错误方向漂移。
2. **默认模式防护弱**（#1、#2），恰恰是上电默认走的模式。
3. **学习窗口设计互相矛盾**：大误差段才学习、近目标全冻结（#11），而注塑压力闭环的精度诉求恰恰集中在近目标段。
4. **每段全量复位**（#14）使在线学习难以积累，削弱了相对固定参数 PID 的核心卖点。
5. 自适应引入**逐周期不确定性**，与注塑工艺要求的可重复性/可追溯性存在张力。

## 5. 注塑机各动作适用性评估

前提：开合模、射胶、顶针等动作以**位置/速度环**为主，压力闭环仅在 `HYD_MODE_PRESSURE_CLOSED_LOOP` 段介入（motion_control.c:2121）。因此 RBF-PID 的真实作用面是**保压、储料背压、泄压/稳压**类阶段。

| 动作 | 压力环角色 | RBF-PID 适用性评估 |
|---|---|---|
| 开合模 | 不参与（位置/速度序列；低压护模是监测逻辑，不走此闭环） | **不适用也不需要**。除非特殊工艺（抽芯保压等），无需引入压力自适应 |
| 射胶 | 充填段为速度环主导；V/P 切换后保压段才进入压力闭环 | 保压段是 RBF-PID 最合理的落点，但保压通常仅数秒，学习尚未收敛段已结束；叠加 #14 的复位机制，收益有限。**建议保压用经典 PI + 前馈**，RBF 作为可选项灰度 |
| 储料（塑化背压） | 背压闭环，对象慢、扰动多（螺杆转速、材料粘度批次漂移） | **理论上最适合自适应的场景**（粘度漂移确实需要增益跟踪），但当前实现每周期复位、默认模式防护不足，需先修 P0。修复前用背压 PI 足够 |
| 顶针 | 位置/速度 + 力限制 | **不适用**。力限制建议走压力监测/限幅，不需要压力伺服闭环，更不需要自适应 |

**综合判断**：该算法在注塑机的合理定位是"保压/背压段的实验性可选策略"，而非通用动作控制器。用于开合模、射胶充填、顶针均不合适。

## 6. 评审结论与建议路线

**结论**

1. 框架完整度中等偏上，经典 PID 分支质量高、可用于生产；RBF 分支存在 5 项 P0 级问题，**不建议在修复前用于生产**。
2. 对注塑场景，RBF 在线自适应的边际价值有限且牺牲可重复性；文档宣称的 Smith 预估与在线增益辨识未实现，"自适应"能力实际弱于文档描述。

**建议路线（按优先级）**

1. **修复 P0（#1-#5）**：统一数值防护、权重钳位、初始增益入窗、前馈开关接线或删除、修正更新顺序。
2. **补齐一致性（#6-#14）**：采样周期归一、钳位按量程缩放、接入压力滤波与死区配置、统一负流量阈值、RBF 分支接入前馈、取消或降频网络复位。
3. **清理死代码与魔法数字（#15-#16）**，修正单位注释（#11）。
4. **策略定位**：生产默认使用经典 PID/PI + 设定值斜坡 + 前馈 + 段级配方参数（recipe 化）；RBF 保留为可选实验策略，并增加自适应参数日志以便追溯。
5. **更务实的自适应形态**：将 RBF 辨识用于**离线整定**（记录生产数据、离线辨识后把参数写回配方），既保留自适应收益，又不牺牲注塑工艺的可重复性。
6. 为上述修复补充回归测试（现有 `tests/rbf_pid_test.c`、`tests/test_pressure_controller.c` 可作为基线扩展，重点覆盖 NaN 输入、模式切换、负流量死区边界）。
