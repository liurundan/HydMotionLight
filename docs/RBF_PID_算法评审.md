# RBF-PID 压力闭环算法评审文档

> 评审对象：`src/rbf_pid.c` / `include/rbf_pid.h`，结合 `src/pressure_controller.c`（集成路径）与 `src/sim/PressureModel.c`（被控对象模型）
> 评审视角：RBF 神经网络 + PID 自适应控制理论、注塑机液压压力闭环工程应用（开合模 / 射胶 / 保压 / 储料 / 顶针）
> 结论摘要：**该实现能跑、有大量工程保护，但"RBF 自适应"的核心机理在数学与工程两个层面均存在硬伤，当前形态更接近"带一层无效神经网络装饰的限幅增量 PID"。建议在保压/射胶等关键工况下不要依赖其自适应能力。**

---

## 0. 一句话给决策者

把神经网络那部分整段删掉，用一个固定增益的增量 PI + 前馈 + 抗饱和，注塑机压力闭环的表现几乎不会变差，代码量和验证成本却能砍掉一大半。这是我反对当前 RBF-PID 方案的根本理由。下面逐条给证据。

---

## 1. 算法结构还原（先说它到底在算什么）

单个 `RBF_PID_Update()` 周期内的数据流：

```
raw_error = P_set - P_actual
error     = deadband(raw_error)                         // ±0.0005 死区
control_state = {INIT, BOOST, HOLD, RELIEF}             // 基于误差比例分档

step_rbf_nn():                                          // ① 在线辨识
   x = [ du_prev/flow_scale, y_prev1/P_scale, y_prev2/P_scale ]
   h_i = exp(-||x - c_i||² / (2 b_i²))                  // 6 个高斯核
   y_hat = Σ w_i h_i                                    // 网络预测归一化压力
   Jacobian = (P_scale/flow_scale) · Σ w_i h_i (c_i0 - x0)/b_i²
   梯度下降更新 w, c, b（带动量 α=0.05）

step_adaptive_gains():                                  // ② 用 Jacobian 调 PID 增益
   KP += scale·eta_p·error·Jacobian·de
   KI += scale·eta_i·error·Jacobian·error
   KD += scale·eta_d·error·Jacobian·dde
   （全部 clamp 到 [min_K*, max_K*]）

step_incremental_output():                              // ③ 增量式出流量
   du = KP·(e - e_prev1) + KI·e + KD·d_term_filtered
   du += 动态前馈(ref_rate) + 加速度前馈(-0.15·dd_press)
   Output = clamp(u_prev + du, output_min, soft_cap)
```

核心卖点是 ①②：用一个 RBF 网络在线辨识对象 Jacobian `∂P/∂Q`，再用该 Jacobian 驱动 PID 三个增益的梯度整定。**评审的绝大部分问题都集中在 ①② 的数学正确性与工程有效性上。**

## 2. 严重缺陷（会直接影响控制质量 / 正确性）

### 2.1 【致命】自适应窗口窄到让 RBF 失去意义

```c
#define PID_MIN_KP  0.4f
#define PID_MAX_KP  0.6f     // KP 只能在 0.4~0.6 之间动，1.5× 跨度
#define PID_MIN_KI  0.0018f
#define PID_MAX_KI  0.0056f  // 3× 跨度
#define PID_MIN_KD  0.015f
#define PID_MAX_KD  0.035f
```

- RBF-PID 的全部理论价值在于"对象特性变化时，网络辨识出新的 Jacobian，把增益推到合适的量级"。而这里 KP 被死死锁在 `[0.4, 0.6]`，**辨识结果再准也只能在 ±20% 内微调**。
- 注塑机压力对象的增益 `∂P/∂Q` 在不同工况间的变化是**数量级**的：射胶充填段（模腔在扩张，油液刚度低）与保压段（模腔封死，油液体积模量 `beta_oil≈1.2e9 Pa` 主导，`dP/dt = beta/V·Q` 极快）之间，`K` 相差几十倍。用一个 1.5× 的窗口去覆盖数量级级别的对象变化，**自适应能力从设计上就是不足的**。
- 反过来，`PID_MIN_KP=0.4` 这个下限还有害：在保压/顶针到位这类高增益、低阻尼工况，需要的其实是**更小**的 KP 以避免超调，但算法被禁止把 KP 降到 0.4 以下。

> **反对理由 1**：既然增益被限死在窄窗内，那 ①②整套神经网络就是在为一个几乎不动的量做昂贵的在线梯度计算——付出了神经网络的复杂度、验证成本和数值风险，却拿不到自适应的收益。

### 2.2 【致命】Jacobian 的符号与量纲一致性无保证，且直接乘进增益更新

增益更新的方向完全由 `error · Jacobian · de` 的符号决定：

```c
pid->KP += learning_scale * pid->eta_p * error * pid->Jacobian * de;
```

- Jacobian 由网络权重 `w_i` 与核输出实时计算，`w` 初始化为 `0.05·(i-2.5)/2.5`（**有正有负**），核中心 `c` 初始化为一个人为线性铺开的值。这意味着**冷启动阶段辨识出的 `∂P/∂Q` 完全可能是负号**。
- 物理上 `∂P/∂Q > 0` 恒成立（泵流量增大 → 腔压升高）。一旦网络在收敛前给出负 Jacobian，增益就朝**错误方向**整定：本该增大的 KP 被减小，甚至撞到 `min_KP` 下限被"焊死"，闭环响应劣化。
- 代码用 `clamp(Jacobian, -5, 50)` 允许了负 Jacobian 通过，等于承认了错误符号的存在，却没有任何"强制 Jacobian 非负"或"符号钳位"的保护。
- 更隐蔽的问题：`step_adaptive_gains()` 里 `error` 已过死区，而 `Jacobian` 用的是 `raw_error` 分档下的网络状态，KI 更新项写成 `error·Jacobian·error`（即 `error²·Jacobian`），**平方项恒非负**，KI 的调整方向此时**只由 Jacobian 符号决定**——Jacobian 一旦为负，KI 单调被推向下限，积分作用被抽空，稳态误差消不掉。

> **反对理由 2**：把一个符号都无法保证的在线辨识量放进增益的反馈更新回路，是把"辨识误差"直接耦合进"控制稳定性"。工业压力闭环不应该接受这种额外的、无收敛保证的失稳来源。

### 2.3 【严重】RBF 在线辨识没有收敛性 / 持续激励（PE）保障

- RBF 三组参数 `w/c/b` 用一阶梯度 + 动量在线更新，学习率 `eta_w=eta_c=eta_b=0.005`。这类在线辨识要收敛，需要输入 `x` 满足**持续激励条件**。
- 但注塑保压段的典型工况恰恰是"设定值恒定、压力稳定"——`x=[du_prev/scale, y1, y2]` 几乎不变，核输出 `h` 长期不变，**没有激励，网络参数随机漂移或停滞**，辨识出的 Jacobian 与真实值脱节。
- 代码没有任何"辨识可信度"评估（如预测误差 `error_rbf` 的持续监控、协方差/信息矩阵条件数检查）。`y_hat` 与真实 `y` 差多少，从不用来决定"是否信任 Jacobian 去调增益"。**辨识与自适应之间缺一个门控**。
- 归一化基准还会跳变：`RBF_PID_SetPressureNormalization()` 在每段按 `pressureCeiling` 或 `targetPressure·3` 重设 `pressure_scale`，而网络的 `c/b` 是在旧 scale 下学到的——scale 一变，输入空间被整体缩放，已学到的核位置全部失配。头文件自己都注明了"运行中改变会导致归一化基准跳变"。

> **反对理由 3**：一个在关键稳态工况（保压）下拿不到激励、又没有可信度门控的在线辨识器，其输出不可信；而算法却无条件地用它去调增益。

### 2.4 【严重】每次降压 / 换策略就 `RBF_PID_Reset()`，学习成果被反复清零

`pressure_controller.c`：

```c
needsAdaptiveReset = trackingRequested ||
    !state->rbfInitialized ||
    (input->targetPressure + 1e-6 < (HYD_REAL)state->rbfPid.P_set);   // 目标下降即重置
...
RBF_PID_Reset(&state->rbfPid);   // 内部就是 RBF_PID_Init，全 memset + 重新铺 c/w/b
```

- 注塑循环里"目标压力下降"极其频繁：保压多级递减（高保压→低保压）、保压转背压、射胶转保压后的泄压……**每一次降压都会把整张网络推倒重来**。
- 神经网络自适应的价值来自"跨周期积累对象知识"。这里每个周期、甚至每一段都在重置，**网络永远停留在冷启动的未收敛状态**，2.3 的问题被放大成常态。
- `RBF_PID_Reset` 直接调 `RBF_PID_Init`，连用户通过 `SetParamLimits/SetLearningRates` 配的窗口和学习率都被 memset 掉，然后靠 `HYD_ApplyRbfPidConfig()` 再灌一遍——这条"reset→重配"的时序脆弱且重复，任何一个 setter 漏调都会静默回落到内置默认。

> **反对理由 4**：一个"学到的东西每次降压都丢光"的自适应器，本质上等价于一个反复冷启动的定增益控制器，却背着神经网络的全部包袱。

### 2.5 【严重】增量式 + 增益在线变动 = 破坏增量 PID 的基本前提

增量式 PID `du = KP·Δe + KI·e + KD·Δ²e` 成立的前提是 **KP/KI/KD 在相邻拍近似恒定**。而这里每一拍 KP/KI/KD 都被 RBF 更新过：

- 位置式展开下，增益突变会在 `u` 上引入与历史误差乘积相关的阶跃扰动。增量式虽然把绝对积分项藏进了 `u_prev`，但 `KI·e` 这一项在 KI 变化时，等效积分基准发生漂移，**产生无法解释的输出脉动**。
- 这一点在保压段（要求压力平滑无纹路）尤其危险：输出流量的小脉动经过泵 → 油液刚度 `beta/V` 放大，直接表现为**制品表面压力波纹 / 保压压力毛刺**。

### 2.6 【中等】多处魔法系数与硬编码，缺乏物理依据与可整定性

- `RBF_PID_ACCEL_FF_GAIN = -0.15f`、`RBF_PID_DYNAMIC_FF_GAIN = 0.001f`：加速度前馈和动态前馈增益直接硬编码在 `.c` 里，违反项目约束（`CLAUDE.md` §14B：调参型浮点阈值应进 `hyd_config.h`）。
- 稳态判据 `e_steady=5.0 bar`、`delta_u_steady=2.0`、`t_steady=0.2s` 全部写死；`5.0 bar` 对 250 bar 量程是 2%，但对 20 bar 的低压顶针工况就是 25%，**判据不随工况缩放，物理意义不一致**。
- `control_state` 分档阈值 `0.02`、`-0.01·setpoint`、学习率缩放 `{0.10,0.25,0.50}` 等，均无标定来源，属于"仿真里试出来的数"。

### 2.7 【中等】控制状态机与前馈的耦合会在过渡段引入反向作用

- `RELIEF`（泄压，`raw_error < -0.01·setpoint`）状态下 `learning_scale *= 0.50`，同时加速度前馈 `f_uff = -0.15·dd_press` 生效。泄压时压力在快速下降，`dd_press` 符号多变，`-0.15` 的前馈可能**在泄压过程中反向加流量**，与泄压意图冲突。
- 注塑"射胶→保压"切换（速度控制转压力控制，即 V/P 切换）瞬间，压力会有冲击尖峰，此时 `control_state` 在 BOOST/HOLD/RELIEF 间快速跳变，学习率缩放随之跳变，**增益整定在切换瞬间最不稳定**——恰恰是最需要稳的时刻。

## 3. 与注塑机实际工况的逐项对照

| 工况 | 对该算法的要求 | 当前实现的表现 | 判定 |
|---|---|---|---|
| **合模 / 锁模** | 高刚度对象，`beta/V` 大，需低增益防超调 | KP 下限锁 0.4，无法进一步降低；tie-bar 刚度使对象增益远超�narrow 窗 | ✗ 自适应窗覆盖不足 |
| **射胶充填** | 对象增益随位置变化（熔体阻力 ∝ 位置），需真正的自适应 | 充填是位置/速度模式为主，压力环多作限压；RBF 无激励 | △ 价值有限 |
| **V/P 切换** | 切换瞬间抗冲击、无积分饱和 | 切换即 `needsAdaptiveReset`→网络重置 + 状态机跳变，最不稳 | ✗ 高风险时刻 |
| **保压（多级递减）** | 稳态精度高、无纹路、平滑降压 | 每次降压 `RBF_PID_Reset`；稳态无 PE 辨识漂移；KI 受 Jacobian 符号影响可能被抽空 | ✗ 核心工况反受其害 |
| **储料 / 背压** | 恒背压，稳态为主 | 同保压：稳态无激励，辨识停滞 | ✗ |
| **顶针** | 低压（10~30 bar）小行程，量程小 | 稳态判据 `5 bar` 死值对低压量程过粗；KP 下限过高易超调撞件 | ✗ 判据不随量程缩放 |

**结论**：该算法自我宣称的"自适应"在注塑最需要它的两类场景（保压稳态、V/P 切换过渡）里，要么无激励失效，要么在最脆弱时刻重置/跳变。它唯一能稳定工作的区间，恰恰是定增益 PI 也能轻松胜任的区间。

## 4. 数值与实现层面的具体问题清单

1. **`rbf_pid.c:296` Jacobian 只取 `x[0]`（=du_prev）方向偏导**，即只对"上一拍流量增量"求偏导，而非对当前控制量 `u` 求偏导。增量式下 `∂y/∂(du)` 与 `∂y/∂u` 概念混用，Jacobian 的物理含义已经偏离"对象稳态增益"。
2. **`rbf_pid.c:457` `du = KP·(error - e_prev1) + KI·error + KD·d_term`**：这里 `error` 已过死区，而 `e_prev1` 存的也是过死区值，死区边界附近会产生 `Δe` 的不连续跳变（±0.0005 的台阶），叠加高 `beta/V` 后可见。
3. **PI 模式与 PID 模式代码路径大量分叉**（`control_mode == PI` 的特判散布在 `sanitize_network`、`same_direction_saturation`、`step_rbf_nn`、`step_incremental_output` 等 6+ 处），PI 模式下还在跑整套 RBF 辨识（只是不用 KD），**为一个"不需要神经网络"的 PI 控制器付了全部 RBF 代价**。
4. **`step_rbf_nn` 中 PI 模式才做 `sanitize_network` 与 `x` 有限性检查**（`:273`），PID 模式不做——PID 模式下若 `du_prev/y_prev` 出现 Inf/NaN，会直接污染整张网络，缺乏对称的健壮性。
5. **`soft_flow_cap = P_set·1.05/K`**（`:373`）依赖外部灌入的 `K`（systemGain）。若段配置没给 `systemGain`（`K=0`），软限幅退化为硬限幅，**软限幅这一保护在最常见的"没配 K"路径上直接失效**。
6. **动量项用 `(w - w_1)` 与 `(ci_1 - ci_2)` 不一致**：权重动量用 `w-w_1`（当前减上一拍），中心/宽度动量用 `ci_1-ci_2`（上一拍减上上拍），**两套动量的时间基准不同**，是明显的笔误级不一致。
7. `network_seed` 头文件注明"仅存储，未接入网络初始化"——**声称支持种子复现，实际没实现**，是误导性 API。

## 5. 被控对象模型（PressureModel.c）侧的评审备注

模型本身质量明显高于控制器，是一个带油液可压缩性（含气修正 `beta_oil→beta_min`）、管路惯性/阻力、泵容积/机械效率、溢流阀迟滞、电机二阶延迟 + 传感器延迟/量化/噪声的**物理标定模型**，还有大量有限性/可容许性守卫与固定 1ms 子步。对评审结论的两点支撑：

- **模型证实了对象增益是强时变的**：`chamber_pressure_delta = beta_chamber/V · q_net · dt`，`beta_chamber` 随压力从 `5e7` 跳到 `1.2e9`（低压含气段 → 高压纯油段），**同一泵流量在低压和高压下产生的压升相差 ~24 倍**。这直接印证 §2.1：任何固定窄窗增益都无法覆盖，而当前 RBF 又被窄窗锁死——两头不讨好。
- **模型的传感器延迟 + 电机二阶延迟**构成真实相位滞后。当前控制器的微分项 `d_term` 用二阶差分 + 一阶滤波（`alpha=0.12`），在这种延迟对象上，在线变动的 KD 极易与延迟相位耦合出振荡——又一个"自适应反而添乱"的隐患。

> 建议：把这个高质量物理模型作为"回归基准台"，用它对比 **定增益 PI+前馈** vs **当前 RBF-PID** 的 ITAE/超调/纹路，用数据坐实本文结论（见 §7）。

## 7. 结论与建议（为什么反对，以及替代方案）

### 反对当前 RBF-PID 方案的总结陈词

1. **收益侧**：自适应能力被 1.5×~3× 的增益窗口锁死，且核心稳态工况无持续激励、换段即重置——**神经网络实际贡献的自适应量趋近于零**。
2. **风险侧**：无符号保证的 Jacobian 直接进增益回路、增量式下增益逐拍变动、状态机在 V/P 切换瞬间跳变——**引入了定增益控制器本不存在的失稳来源**。
3. **成本侧**：6×3 的网络、双份动量历史、PI/PID 双路径特判、reset-重配时序——**验证面和维护成本远高于其功能价值**，且违反项目"最简实现"原则。

一句话：**它把一个本可以用定增益增量 PI + 前馈 + 抗饱和干净解决的问题，包装成一个数学上不自洽、工程上收益为零、风险为正的自适应控制器。**

### 建议路线（按投入从小到大）

- **方案 A（推荐，最小改动）**：默认走 `HYD_PRESSURE_CONTROLLER_PI/PID` 定增益路径（`pressure_controller.c` 已有完整实现，含抗饱和 back-calculation、bumpless tracking、测量/微分滤波），把 RBF 路径降级为实验特性、默认关闭。保压/顶针等关键工况明确禁用 RBF。
- **方案 B（若必须保留自适应）**：做三件事把 RBF 从"装饰"变"有效"——
  1. 放开增益窗口到覆盖 `beta` 数量级变化（如 KP 窗口 ≥ 10×），否则辨识无处发力；
  2. 给 Jacobian 加**物理符号钳位**（强制 `∂P/∂Q ≥ 0`）+ **辨识可信度门控**（`|error_rbf|` 超阈值时冻结增益更新）；
  3. 取消"降压即 Reset"，改为**跨周期保留网络**、仅在传感器/量程配置变更时才重置。
- **方案 C（正解，中期）**：用**增益调度（gain scheduling）**替代神经网络——以工况段（合模/射胶/V-P/保压/储料/顶针）+ 压力区间为索引查表定增益，配前馈 `Q_ff = ref_rate·V/beta`。这既能覆盖对象的数量级增益变化（§5 已证明其必要性），又完全可标定、可验证、可离线整定，符合工业压力闭环的可靠性要求。

### 建议的验证动作（用现成物理模型坐实结论）
在 `PressureModel.c` 上跑三段基准场景——(1) 250→150→80 bar 多级保压降压；(2) V/P 切换冲击；(3) 20 bar 低压顶针——对比 **定增益 PI vs RBF-PID** 的 ITAE、超调、稳态纹路 RMS、以及切换瞬态峰值。预期结论：RBF-PID 在这三项上均不优于、甚至劣于定增益 PI+前馈，从而量化支撑上述反对意见。
