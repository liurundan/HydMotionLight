  RBF神经网络输入向量分析
  
  当前4维输入向量（第161-166行）

  float x[RBF_INPUT_DIM] = {
      pid->du_prev / flow_scale,      // x[0]: Δu(k-1)上一拍控制增量
      pid->y_prev1 / pressure_scale,  // x[1]: y(k-1)   上一拍反馈压力
      pid->y_prev2 / pressure_scale,  // x[2]: y(k-2)   上两拍反馈压力
      pid->e_prev1 / pressure_scale   // x[3]: e(k-1)   上一拍误差
  };

  ---
  首先明确：这个RBF网络的本质作用

  看第188行的Jacobian计算：

  jacobian_n += pid->w[i] * h[i] * (pid->c[i][0] - x[0]) / (pid->b_rbf[i] * pid->b_rbf[i]);

  Jacobian仅对x[0]（控制增量）求偏导。网络的本质是被控对象辨识器（Plant Identifier），预测 ∂y/∂Δu，为Kp/Ki/Kd自整定提供梯度信息。

  这决定了输入向量应该反映被控对象的动态状态，而不是控制器内部的误差信号。

  ---
  e(k-1) 的核心问题

  根本原因：被控对象（液压系统）对误差没有响应，只对控制输入 u 响应。把误差加入植物辨识器的输入，在概念上就是错的。

  具体问题：

  1. 稳态时与x[1]线性相关
    - e(k-1) = r - y(k-1)，当设定压力 r 恒定时（HOLD阶段）
    - x[3] = (r - y(k-1))/P_scale = r/P_scale - x[1]
    - 此时 x[3] 与 x[1] 完全线性相关（只差一个常数偏移），输入空间退化为3维，网络的6个中心在4维空间里学到的是一个3维流形上的分布，浪费了一整个维度
  2. 相变时产生虚假相关
    - 注塑机在不同阶段（BOOST→HOLD→RELIEF）切换时，设定压力 r 突变
    - e(k-1) 剧烈变化，而被控对象的真实动态并未突变
    - 网络把"设定值改变"误学为"对象特性改变"，导致Jacobian估计失准，引发参数学习振荡
  3. 中心更新被污染
    - 第209-212行中心更新对所有4个维度同步迭代
    - e(k-1) 的虚假梯度会污染 c[i][3]，间接影响其他维度上中心的分布（通过加权后的归一化距离）

  ---
  技术文献依据

  经典RBF-PID（Liu & Daley 1999，以及国内注塑/液压应用中广泛引用的方案）的标准3维NARX结构：

  x = [Δu(k-1), y(k-1), y(k-2)]

  对应输入窗口 = 1阶控制，输出窗口 = 2阶输出，物理含义是：
  - 当前控制激励 → 对象在当前工作点的响应灵敏度
  - 两个历史输出 → 捕捉液压系统的二阶动态（弹性变形、阀门响应延迟）

  这个结构已在大量文献中针对液压注塑机压力控制验证，6个隐层节点对应3维输入的比例也更合理。

  ---
  推荐方案

  方案A（推荐）：去掉 e(k-1)，降为标准3维

  float x[3] = {
      pid->du_prev / flow_scale,
      pid->y_prev1 / pressure_scale,
      pid->y_prev2 / pressure_scale,
  };

  将RBF_INPUT_DIM 从 4 改为 3，这是最干净的修改，同时6个隐层节点对3维输入的覆盖能力更好。

  方案B（若坚持4维）：用 Δu(k-2) 替换 e(k-1)

  float x[4] = {
      pid->du_prev  / flow_scale,     // Δu(k-1)
      pid->du_prev2 / flow_scale,     // Δu(k-2)← 替换 e(k-1)
      pid->y_prev1/ pressure_scale, // y(k-1)
      pid->y_prev2  / pressure_scale, // y(k-2)
  };

  物理意义：液压系统存在阀门响应延迟，Δu(k-2) 代表延迟一拍的控制输入实际作用效果，是真实的被控对象输入状态，对Jacobian精度有实质性帮助。需要在RBF_PID_Handle 中增加du_prev2
  字段并在每步更新时维护。

  结论：e(k-1) 作为植物辨识器输入在概念上不合理，建议采用方案A（标准3维）。方案B在需要捕捉液压阀门延迟的高动态工况下有额外收益，但需要 du_prev2 的存储和维护。
