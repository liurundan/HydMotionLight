# RBF-PID 自适应压力闭环有效化设计评审报告

> 评审日期：2026-08-21
> 评审对象：`docs/superpowers/specs/2026-08-21-rbf-pid-adaptive-fix-design.md`
> 评审基线：`docs/RBF_PID_算法评审.md`
> 代码范围：`src/pressure_controller.c`、`src/rbf_pid.c`、`src/sim/PressureModel.c` 及其公开头文件/测试
> 结论：**不通过当前设计，不建议进入实现或合并闸门。**

## 1. 决策摘要

当前设计识别出了若干真实缺陷，但提出的修复仍没有闭合“对象模型 → 在线辨识 → 自适应律 → 状态生命周期 → 验收指标”这条链路。它把多个高风险变更绑定在一个补丁中，却没有给出可证明的闭环稳定性条件、辨识可观测性条件、跨工况状态有效性条件，也没有定义与现有 PI/RBF-PI 行为兼容的接口契约。

因此本报告反对按现规格直接实施，理由不是“RBF 一定不能用”，而是当前方案在工业压力闭环上仍属于未经定义和验证的实验算法。继续实施会把增益窗口、神经网络学习、复位生命周期、前馈和量程缩放的风险同时引入保压、V/P 切换和低压顶针等最敏感工况。

建议保留 RBF-PID 为显式选择的非默认实验特性；默认生产路径继续使用已有定增益 PI/PID。若必须保留自适应，应先重写辨识对象和验收契约，再拆分为离线验证、软件仿真、HIL、真实 PLC 四个独立闸门。

## 2. 证据与当前状态

### 2.1 实际控制数据流

- `HYD_PressureController_Execute()` 在 RBF 分支每周期应用段配置；首次运行、请求跟踪或目标压力下降时设置 `needsAdaptiveReset`，随后调用 `RBF_PID_Reset()`，见 [pressure_controller.c:531](/home/dan/project/hdy-motion-light/src/pressure_controller.c:531) 和 [pressure_controller.c:538](/home/dan/project/hdy-motion-light/src/pressure_controller.c:538)。
- `RBF_PID_Reset()` 保存少量基础量程后直接调用 `RBF_PID_Init()`；初始化会 `memset` 整个句柄、恢复默认窗口/学习率并重新铺设网络，见 [rbf_pid.c:530](/home/dan/project/hdy-motion-light/src/rbf_pid.c:530) 和 [rbf_pid.c:593](/home/dan/project/hdy-motion-light/src/rbf_pid.c:593)。
- RBF 输入是 `[du_prev / flow_scale, y_prev1 / pressure_scale, y_prev2 / pressure_scale]`，网络输出预测当前归一化压力，Jacobian 在 `x[0]` 上求导，见 [rbf_pid.c:258](/home/dan/project/hdy-motion-light/src/rbf_pid.c:258) 和 [rbf_pid.c:285](/home/dan/project/hdy-motion-light/src/rbf_pid.c:285)。
- PID 增益由 `error * Jacobian * de/dde` 更新，随后用于增量式输出 `du`，见 [rbf_pid.c:392](/home/dan/project/hdy-motion-light/src/rbf_pid.c:392) 和 [rbf_pid.c:434](/home/dan/project/hdy-motion-light/src/rbf_pid.c:434)。
- 现有稳态判据仍是固定的 `5 bar`、`2 L/min`、`0.2 s`，见 [rbf_pid.c:501](/home/dan/project/hdy-motion-light/src/rbf_pid.c:501)。
- `network_seed` 在头文件中明确标记为只存储、未接入初始化，见 [rbf_pid.h:137](/home/dan/project/hdy-motion-light/include/rbf_pid.h:137)。

### 2.2 仿真对象不是单一“稳态增益”

物理模型用有效体积弹性模量计算动态压力增量：`beta / volume * net_flow * dt`，同时包含管路惯性、阻力、泄漏、溢流阀、电机动态和传感器延迟，见 [PressureModel.c:643](/home/dan/project/hdy-motion-light/src/sim/PressureModel.c:643) 和 [PressureModel.c:655](/home/dan/project/hdy-motion-light/src/sim/PressureModel.c:655)。因此 `beta/V` 是动态 `dP/dt` 相关量，不等同于由泄漏、溢流和负载共同决定的稳态 `dP/dQ`。规格把“beta 数量级变化”直接映射为 PID 增益窗口需求，缺少中间的对象辨识和单位推导。

- 失败中包括现有物理闭环超调门槛（`test_pressure_model.c:894`）和压力模型参数/开环参考不一致。这里不把失败归因于本设计，但它直接否定了设计 §5.3 所要求的“实施前 ctest 全绿”前提，也说明在新增 RBF 基准前必须先处理基线归属和模型版本问题。

## 3. 阻断级缺陷

### 3.1 “Jacobian 偏导语义修正”仍未定义实际可实现的对象

规格承认当前 Jacobian 是 `∂y/∂du_prev`，但 §2.4 只说“改为对流量域输入求偏导并乘正确的 `pressure_scale/flow_scale`”。这不足以把它变成对象的 `∂P/∂Q`：

1. 当前网络没有当前拍的 `u`、实际泵流量或阀开度输入，只有上一拍的输出增量和两个历史压力；单纯改变归一化比例不会增加缺失的状态变量。
2. 对带电机/传感器延迟的一阶动态对象，`∂P[k]/∂du[k-1]` 是带时延的局部离散敏感度，不是稳态压力流量增益。两者进入自适应律的符号、采样时间和单位都不同。
3. 物理模型在溢流、反向流量、泄漏或传感器量化时，测量压力对某一拍输入的局部导数可能接近零、暂时为负或不可辨识。把它硬钳成非负会隐藏模型失配，而不是修复模型失配。

在没有明确输入向量、预测时域、导数定义、离散化因子和单位测试前，设计声称“Jacobian 量纲/符号正确”并不成立。

### 3.2 非负钳位不能构成安全的自适应律

规格 §2.1 的自洽检查认为 `Jacobian >= 0` 可避免 KI 被抽空。但现有更新式是：

```text
KI(k+1) = KI(k) + scale * eta_i * error^2 * Jacobian
```

在 `Jacobian >= 0` 时该项只能增加 KI，除非达到上限；它没有误差代价下降条件、阻尼项、泄漏项或目标增益。换言之，非负钳位把“KI 可能被抽空”改成了“KI 可能单调爬升”，并没有证明闭环更稳定。KP/KD 更新也只是符号乘积加限幅，没有 Lyapunov 条件、参考模型、投影算子或可计算的稳定裕度。

增益 slew-rate 只能限制每拍变化速度，不能证明宽窗口内的任意增益组合对含延迟、饱和和溢流的对象稳定；“窗口是范围、slew 是速度”不是稳定性证明。规格同时要求默认窗口放宽到约 10 倍，又把超调控制交给软限幅，这会把输出不超限误认为闭环不振荡。

### 3.3 预测误差门控不能替代持续激励

设计明确拒绝 PE，仅用 `|y - y_hat|` 超阈值冻结增益。这个兜底逻辑不成立：保压稳态时输入和压力近似常数，网络可以在当前轨迹上产生很小的预测误差，但对流量敏感度仍然完全未被辨识。低预测误差只说明“在已访问的点上拟合尚可”，不说明 Jacobian 可辨识。

同时，规格要求门控时网络参数 `w/c/b` 继续学习。无 PE 时这会允许中心、宽度和权重在未观测方向漂移；等到偶发扰动使预测误差暂时变小时，漂移后的 Jacobian 又会重新进入增益回路。设计没有参数协方差、输入覆盖率、最小激励、冷启动禁用窗口、模型回滚或可信度迟滞定义，因此“可信度门控”仍是单一误差阈值，而不是辨识可信度。

### 3.4 跨周期保留网络的安全边界不完整

取消降压 Reset 的方向可以理解，但“仅在 `pressure_scale`/量程/传感器配置改变时重置”远不足以保证 `w/c/b` 仍然适用。至少还会改变：

- `flow_normalization_scale`、`fMaxFlow`、输出上下限和泵速换算；
- `systemGain K`、采样周期、滤波器、控制模式和前馈开关；
- 阀状态、溢流状态、机械位置、油温、负载刚度和传感器延迟；
- 当前段的输入分布以及网络动量历史 `ci_1/ci_2`、`bi_1/bi_2`、`w_1/w_2`。

当前集成路径还在每周期调用 `HYD_ApplyRbfPidConfig()`，会更新归一化和输出配置并把增益再次 clamp 到段窗口，见 [pressure_controller.c:311](/home/dan/project/hdy-motion-light/src/pressure_controller.c:311)。规格没有定义配置上下文版本、状态有效期、换机/换模隔离、参数快照校验、回滚策略或“保留网络但冻结所有适应”的安全状态。`RBF_PID_ReseedRuntime()` 只对齐运行时历史，不能证明网络参数与新对象一致。

### 3.5 PI 短路与“数值行为不变”相互冲突

规格 §4.3 要求 PI 模式不再运行 RBF，同时“不改 PI 数值输出行为”。但当前 `RBF_PID_CONTROL_MODE_PI` 并不是普通 `HYD_PRESSURE_CONTROLLER_PI`：它仍使用 RBF-PID 的增量式 `du`、软流量 cap、动态前馈、RBF 增益字段和自己的状态历史；普通 PI 则使用带 `dt` 的积分、tracking/back-calculation 和位置式输出，见 [pressure_controller.c:599](/home/dan/project/hdy-motion-light/src/pressure_controller.c:599)。

因此“短路 RBF”有两种互相排斥的解释：

- 保留 RBF-PI 的增量控制器，仅跳过辨识：需要定义固定 KP/KI、输出软限幅和历史状态的兼容契约；
- 改走普通 PI：会改变现有 RBF-PI 的输出和状态语义，不能再声称数值行为不变。

现有测试没有覆盖两条路径逐拍等价、切换时积分连续性或 RBF-PI 的历史兼容性，单纯“测试全绿”不能解决规格歧义。

### 3.6 过渡段符号门控没有完整的控制方向契约

规格建议在 RELIEF 禁用或符号门控 `-0.15 * dd_press`，但没有定义负流量、误差、目标变化和泵方向的统一符号。当前输出还会在压力误差小于 5 bar 时把负流量强制置零，见 [pressure_controller.c:562](/home/dan/project/hdy-motion-light/src/pressure_controller.c:562)。只对前馈项做方向判断，无法覆盖输出限幅、状态机切换、实际泵方向和外层 PumpConverter 的方向映射。

V/P 切换冻结学习率也没有定义冻结持续时间、重新启用条件、切换期间的增益/积分继承和传感器延迟补偿。它可能减少一次跳变，也可能把切换尖峰期间的错误模型固定更久；没有时序测试就不能称为“过渡段抑制”。

### 3.7 量程缩放和硬门限定义仍不足以支撑工业验收

把 `e_steady` 从绝对 bar 改为 `pressure_scale` 比例，只能改变一个判据，不能保证低压顶针的噪声、分辨率、阀死区和输出流量分辨率也按比例缩放。`delta_u_steady` 同样不能简单用压力量程推导，因为它的单位是 L/min，至少需要泵流量上限、泵增益和传感器噪声作为独立尺度。

“所有阶跃/降压场景超调 < 5%”也没有定义降压的超调方向、分母、峰值窗口、初始值接近目标时的归一化方式和稳定时间判据。对 100→50 bar 的下降阶跃，应该区分低于目标的 undershoot 与高于旧目标的残留压力；对 0→100 bar 还要规定传感器噪声和采样窗口。没有这些定义，硬门限会产生不可重复的测试。

### 3.8 一次性绑定过多改动，缺少可归因的实验设计

规格要求同时放宽窗口、改 Jacobian、加门控、保留网络、加 slew、改前馈、改量程判据、短路 PI、改 soft cap、改动量、接入 seed 和软死区。即使最终指标改善，也无法知道是哪项导致改善或回归；如果指标恶化，无法安全回退到某个已验证中间点。

“RBF 不劣于 PI，并在至少一段优于冷启动定增益”的断言还缺少随机种子、初始状态、同一压力模型参数、同一采样/滤波设置、重复次数、置信区间、饱和/故障剔除规则和基线调参冻结规则。当前 `test_rbf_pid_hil` 的主要门槛是“不故障”和“增益在窗口内”，并未证明压力跟踪优于 PI，见 [test_rbf_pid_hil.c:1](/home/dan/project/hdy-motion-light/tests/test_rbf_pid_hil.c:1)。

## 4. 对各项拟议修复的判断

| 设计措施 | 判断 | 原因 |
|---|---|---|
| 增益窗口放宽 | 暂不接受 | 没有从对象辨识结果推导闭环稳定窗口；宽窗口与一阶模型硬超调门槛冲突。 |
| Jacobian 非负钳位 | 不足以接受 | 只遮蔽符号错误，未修复输入/时域/单位定义，也可能使 KI 单调上升。 |
| 预测误差门控 | 不足以接受 | 预测误差不是可辨识性指标；无 PE 时会出现低误差但错误 Jacobian。 |
| 跨周期保留 | 暂不接受 | 缺少上下文版本、失效条件、快照校验、回滚和模式/量程隔离。 |
| 增益 slew-rate | 可作为保护层候选 | 能限制跳变，但不能替代稳定性分析；需要与配置切换、饱和和积分状态一起定义。 |
| 前馈符号门控/切换冻结 | 可作为局部保护候选 | 方向、时序和外层泵方向尚未形成完整契约。 |
| 魔法系数集中配置 | 可接受但非核心修复 | 提升可维护性，不改变算法正确性。 |
| 动量时间基准统一 | 可接受但需独立回归 | 属于明确的实现一致性修复，不能证明 RBF 自适应有效。 |
| seed 接入初始化 | 可接受但非核心修复 | 只改善可复现性，不提供模型正确性或稳定性。 |
| K=0 soft cap 兜底 | 可接受但需物理标定 | “默认软限”必须有单位、对象边界和失效时的安全行为，不能凭 pressure/flow 比例臆定。 |
| PI 路径短路 | 需重写规格 | 与现有 RBF-PI 行为兼容承诺冲突。 |
| 硬死区改软死区 | 可作为局部修复 | 必须以传感器分辨率和阀死区标定，不应单独宣称消除高 `beta/V` 振荡。 |

## 5. 建议的项目决策

### 5.1 当前版本决策

1. **否决当前设计作为实现基线**，不按该规格修改三份核心 C 文件。
2. RBF-PID/RBF-PI 继续保持显式选择的实验功能；生产关键工况默认使用已存在的定增益 PI/PID、tracking 和抗饱和路径。
3. 先解决当前测试基线失败的归属：确认 `PressureModel` 参数/开环参考及压力保持诊断失败是否来自未合并的模型变更，再重新建立全绿基线。

### 5.2 若必须继续做自适应，重新分阶段

**阶段 A：对象和接口契约。** 明确网络输入是当前流量、流量增量还是泵/阀命令，明确预测时域、Jacobian 的单位和离散采样因子；用有限差分或离线辨识数据验证导数符号与量纲。把 `beta/V` 的动态压力斜率与稳态 `dP/dQ` 分开建模。

**阶段 B：可辨识性和安全适应。** 设计最小激励/数据覆盖指标、模型上下文版本、网络参数有效期和回滚快照；在可信度不足时冻结网络和增益，而不是只冻结增益。自适应律需要明确投影、泄漏/遗忘、增益变化上限、饱和处理和稳定裕度。

**阶段 C：可归因仿真。** 先固定 PI 基线，再一次只启用一个变更；对一阶、物理、延迟、溢流、噪声、低压和 V/P 场景重复运行，报告峰值、上/下冲、ITAE、稳态误差、纹路 RMS、饱和时长和故障数。指标定义必须包含下降阶跃的方向和归一化规则。

**阶段 D：HIL 与真实 PLC。** 通过软件门槛后才进入 HIL，再进行带限幅、传感器故障、换段、断续激励和冷启动/热启动的真实 PLC 测试；未经签核不得把 RBF 设为生产关键工况默认策略。

## 6. 实施前的否决清单

下列条件全部满足前，设计仍应保持 **NO-GO**：

- Jacobian 的输入、输出、时域、单位和有限差分验证已写成可执行契约；
- 有持续激励或等价的离线/在线辨识覆盖证明，预测误差门控不再被当作 PE 替代品；
- 网络状态按量程、流量、系统增益、采样周期、控制模式和工况上下文隔离，具备有效期、校验和回滚；
- 自适应律有稳定性论证或明确的保守 gain-scheduling 替代，并覆盖积分、饱和、延迟和负流量；
- RBF-PI 与普通 PI 的行为兼容边界已明确，逐拍回归测试已定义；
- 一阶/物理场景的阶跃、降压、噪声、延迟和 V/P 指标定义完整，基线和修后结果可重复；
- 当前 `ctest` 全绿，新增基准不依赖尚未修复的 PressureModel 参考数据；
- HIL 和真实 PLC 测试覆盖换段、冷启动、热启动、传感器异常、饱和和溢流状态，并有签核记录。

## 7. 最终结论

当前设计可以作为问题清单和实验路线草稿，但不能作为“真正修好 RBF 自适应”的工程设计。它修补了若干表面症状，却没有解决辨识量不等于控制对象 Jacobian、无 PE 时不可辨识、跨周期模型无上下文、增益自适应无稳定性证明以及 PI 兼容契约缺失这五个根本问题。

**最终评审结论：反对按现规格实施；维持 RBF 非默认实验状态，优先采用可标定、可回归、可回退的固定 PI/PID 或增益调度路线。**
