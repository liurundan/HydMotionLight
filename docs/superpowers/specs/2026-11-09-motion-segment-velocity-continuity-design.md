# 运动段之间规划速度连续性设计

日期：2026-11-09

## 1. 目标与范围

本设计只处理运动段之间的速度衔接，优先保证规划速度连续并限制每个 1 ms 控制周期的速度变化。运动段包括：

- `HYD_MODE_POSITION` 位置段；
- `HYD_MODE_SPEED_RAMP` 速度段；
- 位置段与速度段之间的同向切换；
- 同模式段之间的同向切换；
- 运动段反向切换时的先减速到零保护。

本轮不修改运动段与 `HYD_MODE_PRESSURE_CLOSED_LOOP` 之间的速度斜率，也不修改压力模式仿真蠕行模型。压力边界继续使用当前行为，作为后续独立设计的边界。

目标是：

1. 新运动段从上一周期已经发布的规划速度开始；
2. 新段目标速度、终点速度和位置制动包络只决定规划目标，不直接替代当前速度；
3. 目标速度降低时立即进入有界减速，不因从段起始时间重新计算而继续加速；
4. 同向切换不出现一周期清零；
5. 反向切换保持旧方向，先平滑减到零，再切换到新方向；
6. 实际反馈速度不参与运动段速度链的起点选择。

## 2. 现状证据与问题边界

### 2.1 CSV 证据

实验文件 `docs/data_deg/vofa_waveform_20261109_093838_606.csv` 为 1 ms 采样。文件没有直接记录规划速度，因此 `rActPosition` 的差分只能代表仿真反馈速度，不能替代规划器输出。

同一运动链中的几个切换点表现为：

| 时间 | 工艺输入变化 | 差分反馈速度表现 |
| --- | --- | --- |
| 4.885 s | 速度目标 10% → 50%，位置 50 → 60 | 切换瞬间约 18 mm/s，随后继续上升 |
| 5.067 s | 速度目标 50% → 30%，位置 60 → 70 | 切换瞬间约 77.8 mm/s，短暂升至约 82.3 mm/s 后下降 |
| 5.235 s | 速度目标 30% → 10%，位置 70 → 90 | 从约 54 mm/s 平滑下降 |
| 6.857 s | 速度目标 100% → 90%，反向运动 | 速度仍继续增大约数个周期后才进入较慢变化 |
| 7.169 s | 速度目标 100% → 90%，终点速度变化 | 速度保持连续，但反馈斜率出现重新建立过程 |

这些数据证明切换点并非普遍存在单周期速度值跳变，但说明“新目标降低后是否立即以当前规划速度为起点进入减速”需要在规划器输出层验证。反馈曲线不能单独证明规划器是否使用了反馈速度。

### 2.2 当前代码边界

当前规划器已经维护 `HYD_MotionPlannerState.lastTargetVelocity`，位置规划路径也会读取它作为 `previousMagnitude`。但是：

- 速度段的时间计算仍可能以段内 elapsed time 从零重建目标速度；
- 段切换和在线重启路径会调用 `HYD_PrimeSegmentControllers`，规划状态可能被清零；
- 新段重建后是否恢复规划状态取决于模式和调用路径；
- 反馈速度仍可触发安全减速分支，但它不应成为新段的连续性起点。

因此本轮修复重点是“规划状态的保存、恢复和重新基于当前规划速度限幅”，不是修改压力模式或反馈仿真。

## 3. 设计选择

### 3.1 方案比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 使用实际反馈速度作为新段起点 | 反映轴当前运动状态 | 液压滞后、负载扰动和噪声会传入规划斜率，可能产生抖动 | 不采用 |
| 使用新段目标速度作为新段起点 | 实现简单 | 会跳过过渡过程，目标降低或提高时可能出现速度突变 | 不采用 |
| 使用上一周期规划速度作为新段起点 | 命令链确定、速度连续、抗反馈扰动 | 需要覆盖段切换和在线更新的状态恢复路径 | **采用** |

### 3.2 规划状态定义

`lastTargetVelocity` 是运动段连续性的唯一命令侧速度基准，含方向符号：

```text
v_prev = state.lastTargetVelocity
```

不得用 `AXIS_REF.velocity` 或新段原始 `maxVelocity` 替代 `v_prev`。实际反馈速度只用于：

- 位置制动安全包络；
- 反馈超速保护；
- 到位、停稳和诊断判定。

如果没有有效规划状态，首段才从零速度开始。

### 3.3 同向运动段过渡

对同向位置段、速度段以及位置/速度模式切换，规划器区分工艺速度目标与位置制动安全上限。工艺目标或对应过渡时间改变时，从当前已发布规划速度 `v_prev` 建立一次新过渡：

```text
v_start = lastTargetVelocity
v_goal = requested segment velocity target
T = normalized accelerationTime if v_goal >= v_start, otherwise decelerationTime
rate = (v_goal - v_start) / T

each cycle:
    v_ramped = move_toward(v_prev, v_goal, abs(rate) * deltaTime)
```

同一目标和时间在后续周期保持该过渡率，不能每周期用新的剩余速度差重新计算 rate。目标或时间再次改变时，才从当前 `lastTargetVelocity` 重新建立过渡。稳定目标情况下，过渡应在配置时间内到达目标（允许一个控制周期的量化误差）。

位置段的距离制动包络作为独立安全上限：

```text
v_next = clamp_to_position_safety_envelope(v_ramped)
```

候选速度目标和制动包络至少满足：

- 工艺速度目标先受段最大速度限制；
- 制动包络不得用于抬高 `v_ramped`；
- 正常平滑运动时，包络随剩余距离连续变化；
- 若位置反馈异常或已进入安全边界，安全包络允许优先钳低速度，必要时覆盖普通过渡斜率，以避免为了连续性而违反位置安全约束；
- 安全包络覆盖应单独标记或可诊断，并由测试验证输出不超过包络。

普通目标过渡应满足：

```text
abs(v_ramped[n] - v_ramped[n-1]) <= abs(rate) * deltaTime
```

位置安全覆盖时只保证速度不超过安全包络，不把安全覆盖误认为普通斜率过渡。其他约束：

- 加减速时间继续使用现有毫秒契约，并在库内转换为秒；
- 目标不变时不建立新过渡；
- 目标降低时按减速时间建立过渡，不得从段内 elapsed time 重新推导速度；
- 位置制动包络可以使最终输出低于工艺目标，但不能把 `v_prev` 当成反馈速度或新目标速度。

### 3.4 反向运动段过渡

方向判断独立于速度幅值判断。若新段方向与 `v_prev` 符号相反：

1. 保持上一段方向输出；
2. 以新段减速时间将规划速度幅值降至零；
3. 规划速度达到零后，下一周期才切换到新方向；
4. 新方向从零按加速时间建立目标速度。

不允许把正向速度和负向速度直接相减后一次输出，也不允许在同一个周期翻转速度符号。零速周期是方向切换的明确边界，不属于异常。

### 3.5 段切换状态保存与恢复

需要统一审查以下路径：

- 配方段完成后进入下一运动段；
- 直接运动命令的同向替换；
- `MoveContinuousAbsolute` 的 approach/sustain 交接；
- `CONTINUOUSUPDATE` 修改目标速度、位置或加减速时间；
- 位置段与速度段之间的同向切换。

对两个运动段满足以下条件时保留规划状态：

- 前后模式均为位置或速度模式；
- 方向相同，或者进入反向减速流程；
- 不是 Stop、EStop、外部 Abort 或故障安全路径。

保留内容至少包括 `lastTargetVelocity` 和 `lastTargetFlow`。为了让固定目标按配置时间完成过渡，状态可增加固定大小的过渡目标、过渡率和过渡时间标识；不使用动态内存或轨迹缓冲。状态重置/安全输出清零必须在显式停止、急停、故障和真正的新运动会话中执行。普通运动命令替换不能制造一周期零速度。

压力模式边界不纳入本规则，避免本轮改变压力切换行为。

## 4. 模块与数据流

```text
上一周期 planner state
        │
        ▼
v_prev = lastTargetVelocity
        │
        ├── 解析新段方向
        ├── 计算位置/速度候选目标
        ├── 应用最大速度与距离安全包络
        ├── 同向：按 acc/dec 时间限幅
        └── 反向：旧方向减到零后再换向
        │
        ▼
输出 targetVelocity / targetFlow
        │
        ▼
写回 lastTargetVelocity / lastTargetFlow
```

主要实现边界：

- `src/motion_planner.c`：统一候选速度计算、同向斜率限幅和反向零速保护；
- `src/motion_control.c`：统一段切换时的规划状态捕获/恢复，避免安全输出重置破坏连续运动；
- `include/motion_planner.h`：仅在现有状态不足以表达反向阶段时增加最小固定状态；不引入轨迹缓冲或动态内存；
- `tests/test_motion_planner.c`、`tests/test_motion_planner_time_ramp.c`：验证数值不变量；
- 运动集成测试：验证直接命令、连续绝对运动和段切换没有一周期清零。

## 5. 错误处理与安全边界

- 非法加减速时间继续由现有输入校验拒绝；
- 非有限规划值必须输出安全零值并报告已有内部错误路径；
- 普通过渡从 `v_prev` 有界变化；位置安全包络优先级更高，必要时可覆盖普通过渡斜率，但不得输出高于安全包络的速度；
- 反馈速度异常不能替换 `v_prev`，只能触发已有安全减速逻辑；
- 方向反转不能绕过零速边界；
- Stop、EStop、Fault、Abort 的现有安全行为保持不变；
- 压力闭环切换行为保持不变，不把压力模式的 `1 mm/s` 仿真蠕行纳入本轮验收。

## 6. 验证计划

### 6.1 规划器单元测试

增加或调整以下测试：

1. 首段从零加速，1 ms 周期下每周期速度增量受限；
2. 同向目标提高，从上一周期规划速度继续加速，并在配置时间内到达目标；
3. 同向目标降低，第一周期立即进入减速，不继续按段 elapsed time 加速；
4. 过渡中目标或时间改变时，从当前 `lastTargetVelocity` 重新建立过渡；
5. 位置段目标改变时，距离安全包络降低目标速度；正常运动应连续，安全覆盖场景须保持在包络内；
6. 位置段与速度段同向切换，首个新段输出等于或接近上个周期规划速度；
7. 反向切换保持旧符号，先到零再切换符号；
8. 加减速时间为零或小于最小值时仍有限且连续；
9. 反馈速度故意设置为与规划速度不同，确认规划起点仍来自 `lastTargetVelocity`；
10. 同一个目标重复更新不重置过渡率或引入额外速度变化。

### 6.2 运动集成测试

覆盖：

- 位置段 → 位置段；
- 速度段 → 速度段；
- 位置段 → 速度段；
- 速度段 → 位置段；
- 同向直接替换；
- 反向直接替换；
- `MoveContinuousAbsolute` approach → sustain。

每个测试记录 `STATE.plannedVelocity`、`_plannerState.lastTargetVelocity`、`AXIS_REF.velocity` 和段标识，至少断言：

```text
plannedVelocity[n] 与 plannedVelocity[n-1] 连续
普通过渡下 abs(plannedVelocity[n] - plannedVelocity[n-1]) <= 斜率上限 * 1 ms
同向切换无一周期清零
反向切换不直接翻转符号
```

若安全包络覆盖普通斜率，测试应验证覆盖已发生、输出仍处于包络内，且后续周期按安全目标平滑恢复。

### 6.3 CSV 对照

现有 CSV 只能用于反馈趋势对照，不能作为规划速度连续性的唯一证据。后续仿真应额外导出规划速度和当前段信息，再对照 4.885 s、5.067 s、6.857 s、7.169 s 等切换点。

## 7. 非目标与风险

本轮不实现：

- 运动段与压力段之间的速度/流量斜坡；
- 压力闭环仿真蠕行速度模型修改；
- Jerk 或完整 S 曲线；
- 使用实际反馈速度重建命令侧速度链；
- 自动反向修正或越程策略重构。

主要风险是把“同向命令替换”误判为“全新运动会话”而继承旧状态。控制措施是只在前后均为运动模式、方向兼容且不是 Stop/EStop/Fault/Abort 安全路径时继承；显式停止和安全路径始终清零。

## 8. 验收标准

1. 运动段切换时规划速度从上一周期 `lastTargetVelocity` 开始；
2. 规划器不使用实际反馈速度作为段间速度起点；
3. 新目标速度不直接替代当前规划速度；
4. 同向目标降低时，普通过渡立即减速；只有位置安全包络覆盖时允许更快钳低；
5. 位置/速度模式同向切换无一周期零速度；
6. 反向切换必须先减到零，再切换方向；
7. 压力模式边界行为与本轮修改前保持一致；
8. 相关单元测试和运动集成测试通过；
9. CSV 反馈曲线中的运动段切换点与规划速度导出结果一致。
