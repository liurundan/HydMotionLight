## 1. 结论摘要

| 控制器 | 实用性判定 | 一句话结论 |
|---|---|---|
| 经典 PI（pressure_controller.c） | **基本可用** | 结构标准（条件积分抗饱和 + 微分先行 + 增益调度 + bumpless tracking），主要问题是库内滤波相位滞后与几处语义瑕疵，修小不改大 |

## 2. 当前算法结构梳理

### 2.1 RBF-PID 每拍执行链（RBF_PID_Update）

```
setpoint/feedback → 死区(0.005bar) → control_state 状态机(INIT/BOOST/HOLD/RELIEF)
  → step_rbf_nn：x=[du_prev/du_scale, y_prev1/pressure_scale, y_prev2/pressure_scale]
                   （pressure_scale 默认 250 可经 RBF_PID_SetPressureNormalization 配置）
                   前向计算 Jacobian
      └─ is_steady（|e|<10bar 且 |Δe|<10bar）→ 冻结网络学习与(后面的)增益整定
  → step_incremental_output：
      du = KP·Δe + clamp(KI·e, ±0.08) + KD·(e−2e1+e2)   [D 无滤波]
      Output = u_prev + du + f_du_ff + f_velfb           [f_velfb 经 u_prev 累加成比例反馈，见 4.2 v3]
      clamp(output_min, soft_output_max)
  → step_adaptive_gains（仅 !is_steady 时）：
      KP += ηp·e·sign(J)|J|·Δe
      KI += ηi·e·sign(J)|J|·e − λ·KI                     [L2 衰减]
      KD += 强制唤醒 / 绝对值整流（单向性，见 4.6）
```

### 2.2 经典 PI 每拍执行链（pressure_controller.c 非 RBF 分支）

```
measured → 库内一阶低通(α=0.1) → error = target − filtered（段死区）
  → P：kp·e（kpHigh 按误差比例增益调度）
  → I：integral += ki·e·dt，条件积分（饱和同向时冻结）+ 积分限幅
  → D（PID 策略时）：−kd·filteredPressureRate（微分先行，经 α=0.05 二级滤波）
  → output = clamp(ff + P + I + D, outputMin, outputMax)
  → 负流量死区：error > −2bar 时禁负流量
```

结构骨架是教科书式的，问题在参数语义与细节。

## 3. 分场景实用性评估

| 场景 | 工艺特征 | 经典 PI | RBF-PID | 主要风险点 |
|---|---|---|---|---|
| 开合模（低压模保） | 压力 <10 bar，防夹伤 | 可用 | 可用：稳态冻结使低压段等价固定增益 PI（4.1 修正版）；注意死区绝对值与档位匹配 | 模保段压力精度靠 P+残余 I |
| 开合模（高压锁模） | 快速升压至 150~250 bar | 可用 | **有优势**：f_velfb 升压段比例反馈（4.2 v3）提前抵消积分爬升压超调，上机曲线已证实 | 窗口钳位限制过渡段自适应行程（4.3） |
| 顶针 | 短行程、压力冲击大 | 可用 | 基本可用：f_velfb 比例反馈有效；注意 D 无滤波（4.5）在冲击段的纹波注入 | 制品顶伤 |
| 射胶（V/P 切换→保压） | 切换瞬态 + 长时保压 | 可用（tracking 机制完整） | 可用：切换后冻结策略避免保压段纹波自激；目标下调不复位（4.8）仍需处理 | 保压段压力漂移 |
| 储料背压 | 低压 5~30 bar、低转速 10~40 rpm、纹波相对幅值最大 | 基本可用 | 风险集中段：过渡段学习信号被 2~9Hz 纹波污染（4.1 修正版）；KD 棘轮只增不减（4.6）；RELIEF 无泄压处理（4.9） | 背压波动 → 熔料密度不均 |

## 4. 缺陷清单（按严重度分级）

### P0 — 结构性缺陷，上机前必须处理

> v2 说明：原 4.1/4.2 经上机证据改判为"验证有效的策略"（保留并工程化），不再列为缺陷，正文保留于此仅维持编号连续；当前 P0 实际剩 4.3（窄窗口钳位）与 4.4（Jacobian 无监督）两项。

**4.1 稳态冻结死区 10 bar —— 策略正确（上机验证），工程细节待打磨**
`rbf_pid.c:264 STEADY_DEAD_ZONE 10.0f`：|e|<10 bar 且 |Δe|<10 bar 即冻结网络学习 + 增益整定。

**v2 修正（依据上机实验）**：初版将此判为"自适应名存实亡"的缺陷，**定性错误，予以撤回**。上机证据表明：持续开启自适应时，13 齿齿轮泵的流量脉动（保压转速 10~40 rpm 对应 2~9 Hz）会被 RBF 学习器当作有效激励信号——梯度项 η·e·J·(...) 对纹波是零均值噪声，但噪声整定使增益围绕平衡点持续抖动，反而**增大稳态纹波**。"稳态冻结"使保压段退化为固定增益 PI，恰好规避了这一污染路径，是**经上机验证的有效策略，予以保留**。

遗留的真实问题是工程粒度，而非策略本身：
1. **死区绝对值不与压力档位挂钩**：10 bar 对 250 bar 锁模段（4%）合理，对 5~30 bar 储料背压段则覆盖整个工作区间，背压段自适应全程不生效——该段恰恰是非线性（含气油液刚度塌缩）最强、最需要自适应的工况。
2. **无时间确认**：单拍满足 |e|<10 即冻结，升压末端穿越 10 bar 窗口的短暂瞬间也会误触发冻结/解冻切换，建议加 N 拍持续确认。
3. **两套稳态判据矛盾且都卡低压段**：`STEADY_DEAD_ZONE 10.0f`（冻结用，rbf_pid.c:264）与 `rbf_pid_step_steady_state` 的 `e_steady=5 bar`（rbf_pid.c:521，Status 用）语义重叠但阈值不一。更严重的是后者末尾 `fabsf(pid->P_set) > 5.0f`（rbf_pid.c:546）硬性门限——**P_set ≤ 5 bar 的低压段（模保、5 bar 背压）永远不可能置 steady_state=true、Status 永远停在 2**，即使实际已稳定。这使上层无法据 Status=3 判断低压段稳定，影响段切换与诊断。应将 5.0 改为相对值或去除该门限。

→ 修正方向见建议 #2：冻结策略保留，死区改相对值 + 时间确认 + 判据统一；**不建议**恢复保压段持续学习。

**4.2 压力速度前馈 f_velfb —— 有界比例反馈项（上机验证有效，v3 纠正机制定性）**
`rbf_pid.c:505 Output = u_prev + du + f_du_ff + f_velfb`，f_velfb = −0.15·ΔP（rbf_pid.c:485-493），门限条件 `pressure_error > P_set·0.08`。

**v2 修正（依据上机实验与理论推导）**：初版将此判为"未量化隐含积分通道、升压超调头号嫌疑"，**定性错误，予以撤回**。上机曲线已证实引入 f_velfb 后超调量被有效抑制。理论推导（望远镜求和）：

设 f_velfb 从拍 0 起持续生效（压力单调上升段），则输出中由该项累积的分量为：

```
Σ_{i=1..k} (−0.15·ΔP(i)) = −0.15·(P(k) − P(0))
```

逐项相消后，**该通道不是无界积分器，而是一个有界的压力比例反馈通道**：无论升压段多长，其累积贡献只取决于总压升 (P(k)−P(0))，不随拍数发散。这是 f_velfb 抑制超调的根本机制——升压段每拍 −0.15·ΔP < 0 持续累积成 −0.15·(P−P₀) 的负偏置，直接抵消积分项的爬升，压住输出。上机曲线证实了这一效果。

**v4 仿真确认（2026-09-15）**：用 `test_pressure_target_verification.c` 做了 f_velfb 开/关对照实验：
- f_velfb 开：Mp=7.86%，tr=804ms
- f_velfb 关：Mp=10.32%，tr=647ms
- **f_velfb 抑超调 −2.45%（上机观测复现），但拖慢升速 +157ms**

"拖慢升速"是比例反馈的特征——对压力偏离的持续负反馈在升压段抵消驱动爬升。**若是微分项（稳态归零、不进入积分器），不会产生上升时间惩罚**。仿真数据实证了 v3 的"比例反馈非微分"定性。同时也揭示了 f_velfb 的双刃性：修复方向不是简单加大 −0.15，而是需配合升压段增益调度补偿升速损失。

**v3 纠错（数学复核，纠正 v2 的两处机制性错误）**：

1. **"自消除性"结论错误，予以撤回**。v2 称"稳态时 ΔP→0，该项自动消失"——**不成立**。f_velfb 经 `u_prev = Output`（rbf_pid.c:600）累加进积分器，稳态时只是**每拍增量** f_velfb(k)=−0.15·ΔP(k)→0（不再有新贡献），但**累积和** Σf_velfb = −0.15·(P_set−P₀) 作为常值偏置**保留在 u_prev 中不会消失**。该偏置由积分项 KI·e 吸收抵消（增量式 PI 的积分会自动补偿常值偏置），故**不产生稳态误差**，但绝不是"自消除"。正确的表述是："增量自消失、累积常驻、由积分吸收、无稳态误差"。

2. **"等效微分先行 D 通道"结论错误，予以撤回**。v2 称其与 derivative-on-measurement D 通道等效——**机制定性错误**。D 通道（−KD·dP/dt）是**并联项**，稳态归零、不进入积分器；而 f_velfb **经 u_prev 累加**，累积和是 (P−P₀) 的**比例**反馈，稳态保留为常值偏置。两者数学性质不同：f_velfb 的累积效应是"对压力偏离初值的比例反馈"（proportional-on-measurement，参考点 P₀），不是微分。抑制超调的真正机制是"升压段早期建立的比例负反馈提前抵消积分爬升"，与 D 通道的"对变化率的阻尼"是两回事。调参时应按**比例增益**理解 −0.15，而非微分增益。

3. **f_du_ff 同样有界且量级极小，v2"同病"说法过重**。f_du_ff = 0.001·(vel_ref − v_ref_k1)（rbf_pid.c:497），vel_ref = clamp(P_set−last_ref, ±10)（:496）。故 |f_du_ff| ≤ 0.001×20 = **0.02 L/min/拍**，累积和 Σf_du_ff ≤ 0.001×|vel_ref(k)−vel_ref(0)| ≤ **0.02 L/min**——有界且可忽略，不是"同病"。建议从缺陷清单移除，仅补量纲说明即可。

门限 8%·P_set 的语义自洽：**升压段（误差大）比例反馈生效压超调，接近目标（误差<8%）后增量停止累加、累积偏置冻结**，与 4.1 冻结策略配合形成"过渡段比例反馈+自适应、稳态冻结纯 PI"的整体设计。

遗留的工程注意事项（非缺陷，记录备查）：
1. **累积偏置冻结点非稳态值**：门限退出时累积和冻结在 −0.15·(P_at_8%_threshold − P₀)，而非 −0.15·(P_set−P₀)。若升压斜率不同，冻结点不同，最终由积分补偿的量也不同——调参时需注意该偏置的工况依赖性。
2. **ΔP 含纹波分量**：保压段若门限误触发（见 4.14 低压情形），ΔP 中的齿槽纹波会被 −0.15 增益注入输出——幅度 0.15×纹波幅值，有限但可测。
3. **门限无滞回**：单一阈值 8%·P_set 在边界附近可能拍间抖动，建议加滞回带。
4. **参考点 P₀ 漂移**：累积和以首拍 P₀ 为参考，若段间未复位 u_prev，跨段残留偏置会叠加到下一段（与 4.8 目标下调不复位问题相关）。

**4.3 自适应增益每拍被钳到窄窗口**
`pressure_controller.c:343-349` 每拍调用 `RBF_PID_SetParamLimits`（内部 clamp KP/KI/KD），segment 未配 pressureRbfConfig 时窗口为默认 `KP∈[0.4,0.9]`、`KI∈[0.0013,0.0056]`、`KD∈[0.015,0.035]`（rbf_pid.h:24-29）。自适应全程只能在固定窄窗内蠕动——**名义自适应，实际微调**；而窗口本身没有任何工况依据（与压力档位、流量量程均不挂钩）。

**4.4 Jacobian 无符号先验监督，增益整定方向取决于噪声**
`rbf_pid.c:411 grad_Kp = ηp·e·sign(J)|J|·de`：sign(J)·|J| ≡ J，所谓防护数学上无效（abs 下限 1e-6 截断除外）；更根本的是泵控压力对象 ∂P/∂u 符号有明确先验（正），代码未利用——当 RBF 网络把 J 辨识成负值或近零噪声时，增益朝错误方向单调漂移。

**v3 补充**：v2 漏写了 Jacobian 实际有钳位 `rbf_pid.c:308-311 clampf(-5.0, ..., 50.0)`——这是**部分防护**（防止极值发散），但钳位允许 J∈[−5, 0) 的负值通过，**仍无符号先验监督**。即网络若把 ∂P/∂u 辨识为 −3，整定方向就会反相。建议：J<0 时直接置零或冻结该拍增益整定（保持上拍输出），而非仅靠钳位限制幅度。

### P1 — 明显缺陷，影响性能与可维护性

**4.5 D 通道无独立滤波**
`rbf_pid.c:472-474` 微分滤波被注释（`d_term = raw_d_term`，即 e−2e1+e2）。工艺层低通滤波≠D 通道带限：二阶差分对残存纹波放大 ~4 倍，储料背压段 2~9 Hz 齿槽纹波直接进入 du。测量滤波与微分滤波是两个环节，不能以前者替代后者。

**4.6 KD/KI 自适应单向棘轮 —— 稳态冻结可部分缓解，过渡段风险仍在**
`rbf_pid.c:433-449`：KD 更新分三个子分支——①"强制唤醒"（发散+触底，:433-436）`boost = 0.5·|de|·sign(J)` 经 `fmaxf(boost,0)` **只增不减**；②"误差收拢"（error·de<0，:441-443）`fmaxf(grad,0)` **只增不减**；③"误差发散且未触底"（:445）`delta_Kd = grad_Kd_base`（含符号）**可减**。即"只增不减"仅在 ② 和 ① 触底时成立，③ 分支理论可减——但 ③ 仅在 J>0、error>0 发散时 grad_Kd_base>0 仍增，J<0 才反相减（恰是 4.4 的错误方向）。综合看：**正常工况（J>0）下 KD 实际只增不减**，棘轮定性成立，但表述需精确到"②③ 子分支"。

`rbf_pid.c:416-418` KI 梯度项 ηi·e²·sign(J)·|J|：J>0 时恒非负，KI 只涨不跌（λ=5e-4 的 L2 衰减是唯一回拉力，平衡点被误差能量推高）。

**v2 修正（依据上机实验）**：初版称"保压段 KD 锁死上限"需修正——**稳态冻结策略（4.1）在保压段关闭了增益整定，棘轮在稳态不工作**，这解释了上机保压段未观测到 KD 锁死的失稳后果。但棘轮在**过渡段（|e|>10 bar 的学习窗口）仍然生效**：升压段纹波叠加在大误差上，|de| 激励下 KD 单向爬升，进入保压时被冻结在偏高位——高 KD + 无滤波 D 通道（4.5）恰是保压段纹波放大的潜在组合。故维持 P1 定级，但风险窗口从"全程"收窄为"过渡段学习窗口"。

**4.7 RBF 网络输入用增量 du_prev —— 合法做法（非缺陷），v3 撤回原定性**
`rbf_pid.c:271-275`：x=[du_prev/du_scale, y_prev1/pressure_scale, y_prev2/pressure_scale]，du_scale 取 `f_dd_press_prev`（默认 5.0，rbf_pid.c:161-163）。

**v3 纠错（依据用户指正 + 文献）**：v2 称"用增量辨识使被控对象退化为积分环节，Jacobian 物理含义失真"——**定性错误，予以撤回**。du_prev 作为 RBF 辨识输入是**刘金琨早期专著记载的合法做法**，多篇工程论文亦采用。两种输入形式的辨析：

- **u_prev 形式**（x=[u(k−1), y1, y2]）：网络辨识 ȳ=f(u, y1, y2)，Jacobian J=∂ȳ/∂u=∂y/∂u，是对象对**控制量**的灵敏度。
- **du_prev 形式**（x=[Δu(k−1), y1, y2]）：网络辨识 ȳ=f(Δu, y1, y2)，Jacobian J=∂ŷ/∂(Δu)=∂y/∂(Δu)，是对象对**控制增量**的灵敏度。

两者对增量式 PID 增益整定都成立：整定律 `ΔKP=ηp·e·J·Δe` 中 J 的**符号**（决定整定方向）在两种形式下一致——对泵控压力对象 ∂P/∂u>0 且 ∂P/∂(Δu)>0（同号），故方向辨识均有效；J 的**幅值**不同但已被 clamp[−5,50]（rbf_pid.c:308-311）限幅，对整定步长的影响被钳位吸收。**du_prev 形式甚至更贴合增量 PID 语义**——整定对象本就是 Δu 的灵敏度。故 4.7 不再列为缺陷。

`feature/pressure-ripple-suppression` 分支（15ff9f8）将 x[0] 改为 u_prev 的改动应视为**可选替代实现**而非"修复"，本分支保持 du_prev 不变即可。du_scale 命名 `f_dd_press_prev`（"压力二阶差分"）语义含混但功能正确，属命名瑕疵（见 4.16 同类），不影响控制。

**4.8 目标压力下调不再触发 RBF 状态复位 —— 已实现软复位方案（v4）**
`pressure_controller.c:557-558`：`(targetPressure + 1e-6 < rbfPid.P_set)` 复位条件被注释。保压→背压等目标下调工况沿用旧工况学到的网络与增益，无软复位、无增益衰减替代机制。

**v4 修复（2026-09-15，分支 `feature/soft-reset-rbf-target-switch`，提交 6f799ed）**：

原条件被注释的根本原因：`1e-6` 绝对阈值在 ramp 下每拍触发全量 `RBF_PID_Reset`（memset），破坏自适应连续性。修复方案是**软复位 + 相对阈值**，而非恢复原条件：

1. **`HYD_TargetOperatingPointChanged`**：5%·|old| 相对阈值（最小 2 bar），双向判定，避免 ramp 每拍误触发。
2. **`HYD_SoftResetRbfPidState`**：不调 `RBF_PID_Reset`（保留网络权重 w/c/b）；增益收敛到窗口中心（非归 MIN）；bumpless 播种 u_prev=当前输出；清 f_velfb P₀ 参考点消除跨段偏置；清 e_prev/du_prev/steady_count 工况特定历史。
3. **触发逻辑**：首次初始化/策略切换 → 全量 `HYD_SynchronizeRbfPidState`（保留原行为）；工况跳变 → 软复位。

**仿真验证（150→30bar 切换对照）**：

| 指标 | 软复位 | 无复位 | Δ |
|---|---|---|---|
| 建稳 ts | 1663ms | 2080ms | −417ms（快 20%） |
| 下冲最低 | 26.55bar | 24.05bar | +2.5bar（少泄） |
| σ_ss | 0.106bar | 0.137bar | −23% |

软复位经仿真验证确认有益：收敛快 20%、下冲浅 2.5bar、纹波小 23%。**待上机验证后合并 master。**

**4.9 control_state 状态机空转**
`rbf_pid.c:170-185`：BOOST/HOLD/RELIEF 解析后仅存储，不驱动任何学习率分档或输出策略（早期版本的学习率分档已被移除）。RELIEF（超压）状态无任何特殊泄压处理——状态机是死代码，给阅读者虚假安全感。

**4.10 负流量死区两分支不一致**
RBF 分支 `fabs(error)<5.0 → output=0`（pressure_controller.c:584-586）vs 经典分支 `error>−2.0 → clamp[0,max]`（:666-669）：阈值 5 vs 2 bar 不统一；且 RBF 分支直接清零（破坏积分器连续性），经典分支重新钳位（保留语义）。同一库内两种泄压性格。

### P2 — 工程卫生与语义瑕疵

**4.11** 库内测量滤波与工艺层重复（详见第 5 章专项）。
**4.12** RBF 分支 `output->feedbackFlow = rawOutputFlow − feedforwardFlow`（pressure_controller.c:589）：RBF 输出本不含 ff，减 ff 后语义错误（经典分支 feedbackFlow=P+I+D 不含 ff ✓）。诊断字段不可信。
**4.13** `if (pid->pressure_accel_ff_enabled && 1)`（rbf_pid.c:486）死条件；注释掉的 D 滤波、du clamp、`//printf` 调试残留（rbf_pid.c:472-473,499-501）应清理。
**4.14** `near_target_threshold = P_set*0.08`（rbf_pid.c:485）：P_set<1.25 bar 时阈值<0.1 bar，低压段前馈几乎恒触发，行为退变。
**4.15** RBF 死区语义叠加（v3 修正：v2 误判 effectiveTargetPressure 为"隐式死区"）。实际 `pressure_controller.c:574-575` 的 `effectiveTargetPressure = target − ((target−filtered) − error)` 是**死区传递机制**，不是第三层死区：令 raw_err=target−filtered、error=ApplyDeadband(raw_err)，则 effectiveTarget−filtered = raw_err−(raw_err−error) = error。即该写法把**段死区后的误差原样传给 RBF**（使 RBF 内部 raw_error_rbf = 段死区后的 error），避免 RBF 再做一次段级死区截断。真正叠加的只有两层：**段死区（pressureDeadband）→ RBF 内部 0.005 bar 微死区（rbf_pid.c:153-159）**。段死区远大于 0.005 bar 时，RBF 微死区形同虚设；段死区=0 时，RBF 微死区独立生效。两层语义不重复，但 0.005 bar 的存在意义微弱，建议合并为一层显式配置或文档说明职责。
**4.16** `interf_term = clampf(-0.08, ..., 0.08)`（rbf_pid.c:477-478）：积分速率硬编码 ±0.08 L/min/拍，与 fMaxFlow 无量纲适配；字面量为 double 精度。
**4.17** dt=0（丢拍/首拍）时经典分支积分与微分静默跳过，仅靠 P 输出，无诊断标志。

## 5. 专项：滤波移到工艺层后的影响

用户决策（工艺层滤波）是正确方向，但当前库代码尚未对齐，产生三个问题：

1. **双重滤波相位滞后**：库内 `filterAlpha=0.1`（1 ms 下 fc≈16 Hz）+ `derivativeFilterAlpha=0.05`，群延迟约 10~30 ms 进入闭环。保压段液压固有频率低，这点滞后足以吃掉稳定裕度，把"纹波"变成"极限环"。
   → **行动**：库内默认改为直通（`HYD_DEFAULT_PRESSURE_FILTER_ALPHA 1.0`、`HYD_DEFAULT_PRESSURE_DERIVATIVE_FILTER_ALPHA 1.0`），保留字段兼容老配置；文档明确滤波责任在工艺层。
2. **自适应学习信号被污染**：RBF 分支喂给 `RBF_PID_Update` 的是 `filteredPressure`（pressure_controller.c:578）——网络在学一个带 10 ms 人工延迟的对象，Jacobian 相位失真。滤波直通后此问题自动消失。
3. **D 通道失去最后的遮羞布**：库内滤波曾无意中充当了 D 项的纹波衰减器。直通后缺陷 4.5（D 无滤波）会立刻暴露——**滤波直通必须与"D 通道独立滤波恢复"同步实施**，不能只做一半。

## 9. Ksys / K 对 RBF-PID 参数范围与默认值的指导意义（v6，2026-09-16）

> 场景前提：伺服泵控、单泵多缸；IEC 接口可传入伺服**转速 n[rpm]**、**转矩 T[‰Tn]**、**实际位置 θ[deg]**。
> 已通过开环测试获得系统过程增益 `Ksys = P[bar] / n[rpm]`。
> 问题：这个 Ksys 对 RBF-PID 的参数范围与默认值有没有指导意义？

**结论先行：有，而且是目前被完全浪费掉的最强先验。但它的价值不在"调 KP/KI/KD"，而在"定量程、定前馈、定限幅、定 Jacobian 中心"四项——代码里 `systemGain` 字段早就接好了线，却从没被填过真实数据。**

### 9.1 开环实测：Ksys 确实存在且可测

新增探针 `tests/test_openloop_gain_probe.c`（已注册为 ctest），对 PressureModel 施加恒定转速 20s，取后 1s 均值作为稳态压力：

| n[rpm] | Q[L/min] | P_ss[bar] | Ksys[bar/rpm] | K[bar/(L/min)] | t90[ms] |
|---|---|---|---|---|---|
| 2 | 0.040 | 10.80 | **5.400** | 269.99 | 2303 |
| 5 | 0.100 | 27.00 | **5.400** | 269.98 | 2303 |
| 10 | 0.200 | 54.00 | **5.400** | 269.98 | 2303 |
| 20 | 0.400 | 107.99 | **5.400** | 269.98 | 2303 |
| 40 | 0.800 | 215.98 | **5.400** | 269.98 | 2303 |
| 80 | 1.600 | 250.00 | 3.125 | 156.25 | 736 |
| 160 | 3.200 | 250.00 | 1.562 | 78.12 | 301 |
| 320 | 6.400 | 250.00 | 0.781 | 39.06 | 139 |

三条硬结论（均有断言锁定，防回归）：

1. **Ksys = 5.400 bar/rpm，线性度优于 2%**（n = 2~40 rpm 段）。K 不是玄学，是可测常数。
2. **单位换算**：`K[bar/(L/min)] = Ksys × (1000 / D[mL/rev])`。本例 D = 20 mL/rev → K = 5.400 × 50 = **270.0**（探针实测 269.98，吻合）。
3. **K 只在溢流阀以下有效**。n ≥ 80 rpm 后 P_ss 被钳在 250 bar，Ksys 掉到 3.125 且持续下降——**超出线性段后 K 失效，不能外推**。

附带发现（修正此前报告的错误标注）：t90 在 2~40 rpm **全部等于 2303 ms**，即 `2.303·τ`，说明该模型是**一阶惯性环节 τ = 1.0 s**，并非"物理标定模型"。S1/S2 基线仿真实际跑的是 `PRESSURE_MODEL_TYPE_FIRST_ORDER`（`PressureModel_InitParams` 第 385 行默认值），测试横幅写的"物理模型（经典默认参数）"是错的，此处更正。

### 9.2 量纲分析：K 与 KP/KI/KD 的真实关系

增量式 `du = KP·Δe + KI·e + KD·Δ²e`，`du` 单位是流量 [L/min]，e 单位 [bar]，所以 **KP/KI/KD 的量纲全部是 1/K**。展开到位置式（dt = 采样周期）：

| 参数 | 增量式 | 位置式换算 | 当前默认值 | 换算结果 | 物理意义 |
|---|---|---|---|---|---|
| KP | `du = KP·Δe` | `Kp = KP` | [0.4, 0.9] | Kp = 0.4~0.9 | 环路增益 `Kp·K` = 2.16~4.86 |
| KI | `du = KI·e` | `Ki = KI/dt` | [0.0013, 0.0056] | Ki = 1.3~5.6 s⁻¹ | 积分时间 `Ti = Kp/Ki` = **0.16~0.69 s** |
| KD | `du = KD·Δ²e` | `Kd = KD·dt` | [0.015, 0.035] | Kd = 1.5e-5~3.5e-5 | 微分时间 `Td = Kd/Kp` = **1.7e-5~8.8e-5 s** |

**发现 A（KD 事实上失效）**：Td ≈ 1e-5 s，比采样周期 1 ms 还小两个数量级，**D 项数值上等于没有**。要让 Td = 0.02 s（KP=0.9、dt=1ms），需要 `KD = Td·KP/dt = 18`，当前窗口偏低约 **500 倍**。
但**不能盲改**：`d_term = Δ²e`，传感器噪声 σ = 0.4 bar 时 Δ²e 的噪声约 σ·√6 ≈ 0.98 bar，KD = 18 会让 D 项每拍抖 ±17.6 L/min。所以正确顺序是 **先恢复 D 项一阶滤波（`HYD_THRESH_RBF_DERIV_FILTER_ALPHA`，现被注释掉），再按 Td 目标重定 KD 窗口**——这正是第 4.5 条，优先级应由 P2 上调。

**发现 B（KP 不是当前瓶颈）**：把 `PID_MAX_KP` 从 0.9 扫到 8.0（环路增益 4.86 → 43.2，9 倍）：

| PID_MAX_KP | KP·K | Mp | tr | ts |
|---|---|---|---|---|
| 0.9 | 4.86 | 0.10% | 371 ms | 490 ms |
| 2.0 | 10.8 | 0.10% | 371 ms | 490 ms |
| 4.0 | 21.6 | 0.10% | 391 ms | 510 ms |
| 8.0 | 43.2 | 0.10% | 391 ms | 510 ms |

几乎无变化。**原因是升压段控制器全程顶在输出限幅上（bang-bang 阶段），τ_cl = τ/(1+Kp·K) 只在线性区成立，而线性区只剩最后几个 bar。** 所以：**K 对"调 KP"的指导意义很小，别把力气花在这。**

### 9.3 K 真正有用的五个地方（按价值排序）

| # | 用途 | 公式 | 当前状态 | 价值 |
|---|---|---|---|---|
| 1 | **输出量程校验**（防"永远建不上压"） | `P_full = K × outputMax`，要求 `P_full > 1.5 × P_max_process` | ❌ 未做 | **最高**。K 大/量程小时可提前发现硬伤 |
| 2 | **前馈播种** | `u_prev = P_set / K` | ✅ v6 已实现 | tr 371ms，消除积分从 0 爬坡 |
| 3 | **软上限 + 超调驱动** | `min(硬限幅, P_set/K·(1+G·max(0,\|e\|/P_set−2%))·1.05)` | ✅ v6 已实现 | Mp 0.10%、ts 490ms |
| 4 | **Jacobian 中心** | `clamp(0.2K, \|Jac\|, 5K)` 保号 | ✅ v6 已实现 | 加速 RBF 收敛 |
| 5 | **纹波预算反算** | 要求 σ_P ≤ 1 bar → σ_Q ≤ 1/K；再 → σ_n ≤ 1/(K·D/1000) | ❌ 未做 | 可校验伺服能否达标 |

**用途 1 是本报告最想强调的一条。** 举例：某机 K = 50 bar/(L/min)、工艺最高压 150 bar、outputMax = 2 L/min → `P_full = 100 bar < 150 bar` → **这台机在任何参数下都建不到 150 bar**，PID 怎么调都没用。有了 K，这个结论在开机第一分钟就能得出，而不需要现场调三天。

### 9.4 K 对默认值取整的具体建议

| 参数 | 现状 | K 驱动的建议 | 依据 |
|---|---|---|---|
| `PID_MIN_KP` / `MAX_KP` | 0.4 / 0.9（写死） | `KP = (τ/τ_cl_target − 1)/K` | 一阶对象 τ_cl = τ/(1+Kp·K)；**需先标定 τ** |
| `PID_MIN_KI` / `MAX_KI` | 0.0013 / 0.0056 | `KI = Kp·dt/Ti`，取 `Ti ≈ τ` | 积分时间应与对象时间常数匹配；现 Ti=0.16~0.69s 相对 τ=1s 偏快，与"积分项抵消 P 项制动"的实测现象一致 |
| `PID_MIN_KD` / `MAX_KD` | 0.015 / 0.035 | `KD = Td_target·KP/dt`，Td_target ≈ 0.1·Ti | 现 Td ≈ 1e-5 s，D 项失效；**须先加滤波** |
| `outputMax` | 90（拍脑袋） | `outputMax ≥ 1.5·P_max_process/K` | 用途 1 |
| `segment.systemGain` | 0 或 100/30（拍脑袋） | 开环实测填入，分段 K(P) | 见 9.6 |

⚠️ 上表 KP/KI/KD 三行是**理论指导 + 待上机标定 τ 后确认**，本轮未改默认值（扫描显示当前瓶颈不在增益，改了也无收益）。已改的是确定有收益的 2/3/4 三项。

### 9.5 单泵多缸 / 伺服泵控：三个 IEC 信号怎么用

液压是**伺服泵控**而非阀控，这改变了三件事：

**（1）转速 n[rpm] —— Ksys 的分母，也是在线辨识的输入**
- `Q[L/min] = n × D[mL/rev] × ηv / 1000`，ηv 随压力下降（泵内泄漏 `pump_leak_c0 + pump_leak_speed·n`）。
- **K 是非线性的**：低压段含气量大 → βe 小 → K 小；高压段泄漏大 → K 也小。建议**分三段标定**：0–50 / 50–120 / 120–200 bar。
- 齿轮泵 13 齿流量脉动基频 `f = n × 13 / 60 [Hz]`。本仿真保压 n ≈ 18.5 rpm → f ≈ 4.0 Hz，落在实测 2–9 Hz 区间内，模型自洽。

**（2）转矩 T[‰Tn] —— 压力的独立观测量，价值被严重低估**
- 泵轴转矩 `T = Δp·D/(20π·ηm)`，**转矩正比于压力**。三个用途：
  - **压力传感器冗余/交叉校验**：T 估算压力 vs 传感器，偏差超阈值即报传感器故障（这是"防范黑天鹅"里最便宜的一道）。
  - **K 的在线持续辨识，无需停机做阶跃**：稳态时 `P ∝ T` 且 `P = Ksys·n` → `Ksys ∝ T/n`，正常生产中每拍都能刷新 K。
  - **泄漏恶化预警**：同压力下转矩上升 = 内泄漏增加 = K 下降，可提前报泵的容积效率衰退。

**（3）位置 θ[deg] —— 纹波前馈的钥匙**
- 现有 `ripple_compensator` 用 Goertzel 观测器**事后**补偿，存在观测延迟。
- 有了角度就能做**按相位的前馈注入**：在 θ 的特定齿位提前注入补偿流量，无观测延迟，理论上比观测器强一个量级。
- 这是"战胜纹波"最值得投入的方向，但需要先把 sim 纹波按上机数据标定（第 8.6 节的限制仍在）。

### 9.6 当前代码的真实缺口：线接好了，数据没填

```c
/* common_types.h:397-401 —— 字段存在，注释写着"典型值 1-10 bar/(L/min)" */
HYD_REAL systemGain;   /* 系统物理增益 deltaPressure/deltaFlow */

/* pressure_controller.c:396-399 —— 接线也早就通了 */

    RBF_PID_SetGainCompensation(&state->rbfPid, (float)segment->systemGain);
} else {
    RBF_PID_SetGainCompensation(&state->rbfPid, 0.0f);
}
```

**但所有配方与测试里 `systemGain` 要么为 0，要么是 100 / 30 这种拍脑袋值 → 增益补偿事实上从未真正启用。** 这是"机制完备、数据缺失"的典型，也是本次优化收益最大的单点。

**建议的可执行标定步骤（交付给现场工程师）：**

1. 开环，在最大工艺压力的 50% 处做 3~4 个转速阶跃（如 10 / 20 / 30 / 40 rpm），每个稳 3~5τ，记录 P_ss；
2. 线性拟合 `P_ss = Ksys·n` → 斜率即 Ksys；换算 `K = Ksys × 1000/D`；
3. 在 0–50 / 50–120 / 120–200 bar 三段各重复一次 → 得到分段 K(P)；
4. 把 K 写入 `segment.systemGain`；
5. 自检：`K × outputMax > 1.5 × P_max_process`？不满足则报警"量程不足"，不要去调 PID。
